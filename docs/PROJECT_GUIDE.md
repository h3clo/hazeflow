# Haze Flow 프로젝트 가이드 — 현재 작업 인덱스

> 기준일: 2026-11-07. 최신 사용자 지시와 실제 Git/코드 상태가 과거 문서보다 우선한다. 작업 시작에 필요한 내용만 읽고 상세는 관련 문서로 이동한다.

## 시작 순서

1. [AGENTS.md](../AGENTS.md)에서 데이터 보호·작업 범위·검증 규칙을 확인한다.
2. 아래 **현재 시작점**과 **작업 대기열**을 확인한다.
3. `git status --short`, 현재 브랜치·최근 커밋·관련 코드/테스트를 확인한다. GitHub에 없는 로컬 작업을 완료 또는 유실로 단정하지 않는다.
4. 해당 작업의 문서만 읽는다. 제품 원칙은 [PRODUCT_VISION.md](PRODUCT_VISION.md), 소비 데이터는 [payment-ledger-plan.md](payment-ledger-plan.md).
5. 작업 후 완료/미완료, 검증 근거, 배포 여부, 다음 시작점을 갱신한다. 긴 경과는 [handoff-history.md](handoff-history.md)에 남긴다.

## 현재 시작점

**활동 기록 UX (진행 중)**
- 과거 인계 보고: `activity-classify.js`와 `tests/activity-classify.test.js` 작성, 당시 483개 테스트 통과. `app.js`의 `captureView()` 개편 및 이벤트 연동은 미완료 보고. **최신 Git/로컬 코드로 재확인 전까지 확정 완료로 취급하지 않는다.**
- 다음 행동: 로컬 `docs/UX_HANDOFF.md` 존재 여부 확인(현재 GitHub 브랜치에는 없음) → 실제 코드 상태 확인 → 한 줄 기록, 자동 분류·수동 수정, 활동 시작/짧은 기록, 추가 설정 구현·검증.
- 기존 활동·사진·운동·동기화 기록 보존. 사용자 개인 계정 대신 `?sandbox&device=작업별이름` 사용.

**소비 데이터 (방향 전환 결정, 미구현)**
- **결제 내역 우선:** 은행·카드사·현금영수증 → 결제 원장 대조 → 기존 쇼핑몰 주문/상품 연결 → 미연결 거래 사용자 확인 → 필요한 새 쇼핑몰만 추가 수집.
- 다음 행동: [결제 원장 중심 설계](payment-ledger-plan.md) 검토 후 기존 저장 구조/중복/환불 처리와 차이를 조사하고 **안전한 전환 계획부터 작성**. 기존 쇼핑몰 중심 수집을 계속 확대하거나 기존 계정 자료에 즉시 적용하지 않는다.
- 기존 비공개 결제 보완 파일 및 쇼핑몰 검수는 과거 작업 결과로 보존하되 **새 로드맵의 자동 실행 대기열이 아니다**. 필요할 때 [과거 인계](handoff-history.md)와 로컬 `.private/data-locations.md`를 확인한다. 이미 검토한 월을 무조건 재수집하지 않는다.

## 작업 대기열

### P0 · 데이터 보존·실사용 오류
- [ ] iPhone 신규 사진 저장/재접속/Mac 표시 실기기 확인.
- [ ] iPhone ↔ Mac 활동 시작·종료·편집·충돌 및 오프라인 복귀 검증.
- [ ] 저장·삭제·토글·사진·계정 전환의 오래된 화면 충돌 보호 회귀 확인. 실제 계정 기록으로 시험하지 않는다.
- [ ] 좁은 화면·다크모드·입력 중 렌더 오류는 재현된 부분만 수정.

### P1 · 활동 기록 입력 UX
- [ ] 한 줄 입력, 규칙 기반 카테고리 추천, 사용자 선택 우선, 활동 시작/짧은 기록, 추가 설정 접기/펼치기 완성.
- [ ] 기존 저장·동기화·운동 파서 회귀 검증 및 화면 확인. 구현/검사/배포/실기기 검증을 구분.

### P1 · 소비 데이터 구조 전환 (설계 먼저)
- [ ] 은행·카드·현금영수증을 결제 증빙으로 수집·정규화할 수 있는지 출처별 검토.
- [ ] 중복 증빙, 계좌이체·카드대금 납부, 취소/환불, 복합결제, 주문과 결제의 다대다 관계 설계.
- [ ] 기존 네이버·쿠팡·지그재그·11번가·G마켓 주문 자료를 결제에 연결하는 방식 검토.
- [ ] 연결되지 않은 결제만 사용자에게 구매처 확인 요청하고, 확인된 추가 쇼핑몰 자료를 수집하는 흐름 설계.
- [ ] 기존 저장 데이터와 상품 분석을 보존하는 마이그레이션/회귀 검증 계획 작성. **승인 전 실제 계정 데이터 변경 금지.**

### P2 · 기존 기능 완성
- [ ] 운동 세트 빠른 입력·수정, 건강/식단/인바디 비교 및 추정·누락 표시.
- [ ] 공부 일시정지/재개, Obsidian/블로그 연결 실제 동작 검증.
- [ ] 결제와 연결된 검증 상품만 가격·구매 간격·단위가격 분석.
- [ ] 가족·자산·연간 소득/세금 자료의 중복 합산 방지 및 검증.

### P3 · 이후 검토
- [ ] 알림, 외부 AI, 설치형 앱/건강 연동은 별도 승인과 보안·비용 검토 후 착수.

## 검증·배포·인계

```sh
npm ci
npm test
npm run build
git diff --check
```

문서만 바꾼 경우 코드 테스트를 실행했다고 보고하지 않는다. `main` push는 Pages 배포를 유발할 수 있다. 사용자 승인 없는 배포·개인 데이터 수정·무단 재수집 금지. 완료한 작업은 대기열에서 제거하고 다음 시작점을 갱신한다.
