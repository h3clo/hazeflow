# Haze Flow 프로젝트 가이드

마지막 갱신: 2026-11-07. 대상: 사용자와 Codex·Gemini 등 이 저장소를 이어받는 작업자.

이 문서는 제품 의도, 바꾸면 안 되는 결정, 현재 구현과 검증 범위, 남은 작업을 연결하는 기준 문서다. **실행 중인 코드와 실제 Git/배포 상태를 확인한 뒤 사용한다.** 과거 점검 문서의 날짜별 기록은 당시 상태이며 현재의 미구현 목록이 아니다. 최신 사용자 지시와 충돌하면 사용자 지시에 맞춰 이 문서를 갱신한다.

## 0. “프로젝트 이어서 진행해줘”의 현재 시작점

**별도 설명 없이 시작한다.** 먼저 최신 Git/미커밋 변경과 이 절 아래의 마지막 인계 메모를 확인한다. 다음 작업자가 이 절의 작업을 이미 끝냈다면 상태를 갱신하고 6번의 우선순위로 다음 묶음을 선택한다.

- **다음 작업:** 생활 건강 상세의 신체 정보/인바디 저장·체크 값 보존 및 실제 활동 요약 확인은 끝났다. 건강 운동 연결의 합성 화면 흐름과 나머지 미배포 오류 수정 묶음을 점검한다. **사용자는 생활 체크 디자인을 아직 만족하지 않는다. UI는 미완료/미배포이며 임의로 계속 꾸미지 않는다.** 실제 iPhone 검증은 별도다.
- **완료 기준:** 별도 필드 동시 편집 보존, 같은 필드 충돌/안내 정책, 연속 입력, 계정·날짜 전환, 사진 필드 보존, 저장 실패 안내를 실제 저장 경로와 합성 UI로 검증. 사용자의 실제 일기/생활 값을 시험 수정하지 않는다. 설계가 바뀌면 이유와 검증을 남긴다.
- **참조:** `app.js`, `record-edit.js`, `indexed-record-storage.js`, `record-merge.js`, `tests/`, `docs/sync-reliability.md`. 활동 종료 시각 보존과 다른 기록의 병합 로직을 무조건 전체 비교로 대체하지 않는다.
- **자료 작업을 선택할 때:** `.private/data-locations.md` → `.private/data-inventory.json` → `python3 scripts/check-private-data-inventory.py`. 이미 휴지통으로 정리한 사본을 재수집/재삭제하지 않는다.
- **현 배포 기준:** 코드 `41afcbe`, 443 검사·빌드 및 Pages Actions `42287493954` 성공. 후속 문서 커밋이 같은 워크플로를 다시 실행하면 그 실행 번호로 갱신한다.
- **하지 말 것:** 개발 할 일을 앱에 등록, 개인 자료 초기화, 무조건 재수집, 매 변경 즉시 배포, 완료하지 않은 기능을 완료라고 기록.
- **인계 완료 기준:** 새 코드 검사뿐 아니라 이 절의 다음 시작점·6번 미완료 목록·마지막 인계 메모를 함께 갱신한다. AI 이름별로 별도 계획을 만들지 않는다.

## ChatGPT에 넘기는 일

이 컴퓨터의 Cursor 세션에는 아이폰과 로그인된 쇼핑몰이 없다. 아래는 그 화면을 열 수 있는 작업자가 이어서 한다. 주문번호·금액·계정·개인 경로 원문은 공개 문서에 적지 않는다. 자료 위치는 로컬 `.private/data-locations.md`, 대조 숫자는 `.private/shopping-coverage-2026-11-07.md`만 본다.

1. 배포된 웹을 아이폰 홈화면 앱에서 연다. 코드는 `41afcbe`이고, 안내 문서까지 반영된 사이트 커밋은 `7206704`다. 카메라로 새 사진을 찍어 저장한 뒤 앱을 다시 열고, Mac에서도 보이는지 확인한다. 오류 문구, 화면에 나온 버전, 동기화 상태, 재현 순서를 이 가이드 인계 메모에 남긴다. 이미 있는 일기·생활 기록은 시험용으로 고치지 않는다.
2. 같은 버전에서 활동을 아이폰에서 시작하고 Mac에서 종료·수정한다. 반대 순서와, 한쪽 편집창을 연 채 다른 쪽에서 내용이나 종료를 바꾸는 경우도 본다. 종료한 활동이 다시 진행 중으로 보이는지 확인한다.
3. 오프라인에서 기록을 쓴 뒤 다시 연결하고, 앱을 나갔다가 돌아오고, 저장 공간이 부족할 때의 안내를 확인한다.
4. 로그인된 브라우저에서만 남은 쇼핑 원자료를 확인한다. 대상은 네이버·쿠팡·11번가·G마켓·지그재그다. 휴지통으로 보낸 사본은 다시 모으거나 지우지 않는다. 보관한 제안 JSON은 적용하지 않는다. 상품 줄이 없는 주문, 상품 합계와 주문 총액이 다른 주문, 쿠팡 검토 파일에만 있고 취소 상태가 없는 주문, 네이버 결제목록과 저장분이 날짜·금액만으로 같지 않은 차이, G마켓 주문 그룹과 상품 주문번호의 차이를 원문에서 구분한다. 지그재그 환불이 끝나기 전에는 가계부에서 빼지 않는다. 새 파일이 생기면 인덱스를 다시 세고 비공개 대조를 새로 쓴다.
5. 즐겨찾기 삭제와 자산 잔액·계정 삭제의 최신 기록 비교는 이 저장소 작업본에만 있다. 웹에는 아직 배포하지 않았다. 배포는 사용자가 요청할 때 그 코드와 안내를 함께 올린다.

## 1. 어떤 앱인가

Haze Flow는 사용자의 하루를 계획하고, 최소한의 입력으로 실제 생활을 남기고, 나중에 비교·회고하는 개인 생활 관리 앱이다. 웹이 현재 실사용 기반이며 아이폰 홈화면에 추가해 앱처럼 사용한다. 현재는 개인 사용 중심이지만 다른 계정에도 무리 없이 동작하도록 만든다.

중심 질문은 “오늘 뭘 해야 하지?”, “실제로 무엇을 했지?”, “예전의 나보다 어떻게 달라졌지?”다. 식사·운동·감정·공부·돈·몸의 변화를 서로 연결하되 사용자가 같은 내용을 두 번 입력하게 하지 않는 것이 목표다.

단순한 일기 앱이나 모든 정보를 채워야 하는 관리 도구가 아니다. 사용자는 하루 종일 화면을 켜두고 일정과 할 일을 익숙하게 보고 싶어 하며, 차트로 변화를 직관적으로 확인하는 것을 선호한다. 기록량 자체를 성과나 건강 개선으로 단정하지 않는다.

### 주요 이용 흐름

- 오늘: 현재 시각이 기본인 활동 기록, 다음 활동을 시작하면 앞 활동 종료를 연결, 필요하면 시작·종료를 직접 수정.
- 계획: 일정은 캘린더, 반복 루틴은 한 번 설정 후 날짜별 실행 체크, 할 일은 오늘/미래 기한 또는 무기한.
- 대시보드: 할 일 포스트잇과 일정·루틴 캘린더를 함께 보며 모니터에 계속 띄워두는 모드.
- 기록/회고: 하루·주간·과거 날짜의 활동·사진·일기·신체 수치를 다시 확인.
- 공부: 공부 시작 → 결과·다음 행동 → 복습할 질문 → 필요한 것만 Obsidian 노트 → 블로그 초안/글 링크.
- 돈 관리: 거래뿐 아니라 무엇을 얼마나 자주 샀고 같은 단위의 가격이 어떻게 변했는지 확인.

## 2. 여기까지 오게 된 과정과 결정 이유

정확한 모든 대화의 재구성이 아니라, 현재 대화와 저장소에서 확인한 제품 결정의 요약이다.

1. **하루 계획과 생활 기록에서 시작.** 기록만 쌓는 것으로는 부족해 일정·루틴·할 일을 자주 볼 수 있어야 한다는 요구가 생겼다. 계획한 일과 실제 활동은 별도 데이터로 유지하면서 오늘의 흐름에 함께 표시한다.
2. **입력 부담 축소.** “식사”, “운동”을 본문에 직접 적게 하는 대신 카테고리를 선택한다. 활동은 시작/종료 구간으로 다루고 진행 중 상태를 눈에 띄게 표시한다. 모든 작은 행동까지 기록하도록 강제하지 않는다.
3. **기록을 다시 쓰는 구조.** 사진, MD/JSON/PNG 내보내기, 과거 비교, 주간 회고, 즐겨찾기와 요일 추천을 추가했다. 디자인은 단순함과 실용성을 함께 추구하고 기본 select가 동떨어져 보이지 않게 정리했다.
4. **웹 배포와 계정 동기화.** GitHub Pages에 배포하고 Supabase 계정/사진 동기화를 연결했다. 매번 메일 인증을 받기보다 이메일·비밀번호 로그인과 로그인 유지를 선택했다.
5. **생활 전반으로 확장.** 묶음 운동, 근육 부위 선택, 식단·인바디·Apple 건강, 공부, 자산, 가족·소득·세금 자료를 연결했다. 기능은 많아져도 입력 단계와 중복 문구를 늘리지 않는 것이 계속된 요구다.
6. **쇼핑 기록의 목적 명확화.** 쇼핑몰 주문/영수증을 모은 목적은 가계부 합계뿐 아니라 품목별 지출, 휴지·샴푸 구매 간격, 계란 같은 상품의 단가 변화다. 주문 총액만 가져오는 것과 상품별 분석 가능한 데이터는 다르다.
7. **실시간 투자 조회 단순화.** 사용자는 일별 대략적인 자산 평가로 충분하다고 정정했다. 특정 Mac·고정 IP·비밀키에 의존하는 실시간 조회를 제품의 필수 경로로 되살리지 않는다. 타 계정이 못 쓰는 개인 전용 연결을 일반 기능처럼 노출하지 않는다.
8. **신뢰성 우선.** 기기 간 누락, 종료한 활동이 다시 진행 중으로 보임, 같은 기록 충돌, 사진 등록 문제를 반복 점검했다. `The quota has been exceeded`는 기기의 작은 웹 저장 영역 문제였으며 Supabase 사용량이나 RAM 부족이라고 설명하지 않는다. 큰 기록과 전송 대기 내용을 IndexedDB로 이전했다.
9. **현재 단계.** 새 앱 플랫폼보다 웹의 데이터 보존·기존 기능 완성·결제 자료 정리가 우선이다. 개발 로드맵을 앱 할 일에 넣었다가 사용자 요청으로 폐기했다. **앞으로 개발 상태는 이 문서로 관리한다.**

## 3. 제품 규칙 — 후속 AI가 임의로 바꾸지 말 것

- 루틴은 매일 같은 내용을 다시 작성하는 것이 아니다. 요일·단계·적용일로 반복 설정하고 실행은 날짜별로 보관한다. 새 설정으로 과거 실행을 덮지 않는다.
- “할 일”이 현재 화면 용어다. 과거 reminder/미리알림/화이트보드 등의 내부 필드·주소 호환은 유지하되 화면 용어를 다시 섞지 않는다. 현재 모드 이름은 “대시보드”.
- 중량 운동 입력: **kg, 횟수, 세트**. 마이마운틴: **각도, 속도, 시간(분)**. 러닝머신·천계: **속도, 시간(분)**. 0kg은 유효한 기록이다. 한 번의 운동 안에 여러 기구/세트가 들어간다.
- 예상 사용 근육과 사용자가 실제 느낀 부위는 구분한다. 소모 열량·회복은 추정/참고이고 실제 회복 완료를 측정한 것처럼 쓰지 않는다.
- 활동 원문을 보존하는 기능은 있지만 과거 채팅 전체를 원문 메모로 무작정 등록하는 것은 사용자가 원하지 않았다. 실제 행동으로 정리하고 중복 맥락 메모를 만들지 않는다. 자료에 없는 시간/수치는 임의 생성하지 않는다. 특정 과거 기록을 대략 채우라는 지시는 모든 향후 데이터의 추정 허용이 아니다.
- 가격 비교는 같은 품목·단위·수량과 확인한 상품 금액으로 한다. 주문 차액을 상품에 임의 배분하지 않는다. 배송비·할인·부분 반품·포인트를 검토한다. 구매 간격은 소진 간격의 측정값이 아니다.
- 식사와 지출/영수증은 연결해 한 번만 합산한다. 복합 결제도 거래 총액을 중복 합산하지 않는다. 온누리/포인트 등을 무조건 현금으로 뭉개지 않는다.
- 가족 공용 지출도 의미가 있다. 명의자·사용 범위·실제 부담자를 구분하고, 연말정산 공제자료와 실제 가계부 지출은 따로 집계한다.
- 공부 과목은 확장 가능해야 한다. 기본 영어·개발·한국사·정처기 외 사용자 과목 추가·보관을 유지한다.
- 사용자는 차트를 좋아한다. 단위·기간·값(마우스/터치/키보드)·자료 부족을 명확히 하고 긴 원자료 표는 접어서 볼 수 있게 한다.
- 사진을 못 읽거나 저장하지 못하면 오류를 표시한다. 성공하지 않았는데 완료라고 표시하지 않는다. 데이터 손실 우려 시 새로고침/로그아웃/저장소 삭제부터 권하지 않는다.

### 변경 범위와 디자인 유지 원칙

이어서 작업하는 AI는 현재 앱을 완성하는 역할이다. 자율성은 합의된 작업의 실행을 위한 것이며 새로운 기능/디자인 방향을 독자적으로 결정할 권한이 아니다. 모든 AI는 `AGENTS.md`의 “작업 범위와 UI 변경 경계”를 따른다.

|변경 종류|진행 기준|
|---|---|
|기존 기능 버그·저장/동기화·성능·접근성·검사|현재 합의와 데이터/동작을 보존하며 자율 진행|
|겹침·잘림·정렬·다크모드 대비·좁은 폭 오류|기존 스타일 체계 안에서 필요한 부분만 수정|

### Supabase와 IndexedDB 관계

- Supabase: 같은 계정의 기기 사이에서 공유하는 서버 기록·사진.
- IndexedDB: 각 브라우저/홈화면 앱의 기기 기록, 사진 캐시, 전송 대기와 복구를 위한 저장소. Supabase와 대체 관계가 아니다.
- 일반 기록/백업 스냅샷: `hazeflow-snapshots-v1`의 `records`. 전송 대기: `hazeflow-records-v1`의 `journals`. 사진은 별도 IndexedDB. 작은 테마·로그인 설정은 localStorage/sessionStorage에 남을 수 있다.
- 모든 쓰기는 트랜잭션 완료를 기다린다. 오래된 화면의 캐시를 저장 원본으로 믿지 않는다. 계정 변경 중 늦게 도착한 응답이 다른 계정에 반영되지 않게 한다.
- 이전 앱이 비어 있는 계정으로 오해하지 못하도록 마이그레이션 표식을 남긴다. 전송 대기/충돌이 있는데 저장소를 지우지 않는다.
- 오프라인 기록은 열린 화면과 정상 저장소에서 가능하다. **오프라인 상태로 앱 화면을 처음/새로 여는 기능은 아직 보장하지 않는다.**

## 7. 여러 AI가 번갈아 작업하는 절차

### 시작

1. 최신 사용자 요청과 `AGENTS.md`, 이 가이드의 현재 상태/인계 메모를 읽는다.
2. `git status --short`, `git branch --show-current`, `git log -5 --oneline`을 확인한다. 미커밋 변경이 있으면 작성자/목적을 확인하고 보존한다.
3. 현재 배포/브랜치가 문서와 달라졌으면 실제 소스와 Actions를 확인한다. 다른 AI가 작업 중이면 같은 파일을 동시에 고치지 않는다.
4. 이번에 끝낼 범위를 정하고 해당 코드/분야 문서만 추가로 읽는다. 사용자에게 이미 제공한 정보나 승인 범위를 매번 다시 묻지 않는다.

### 모든 AI가 같은 문서를 함께 유지하는 규칙

- 이 문서는 Codex 전용이 아니다. Gemini 및 다른 AI도 직접 수정하며, 다음 작업자는 최신 파일/변경 내역을 읽어 그 작업을 이어받는다. 작성자에 따라 우선순위를 두거나 과거 채팅 기억으로 되돌리지 않는다.
- 사용자 최신 지시 → 실제 코드·재현·검증 근거 → 최신 인계 메모 순으로 상충 내용을 확인한다. 날짜가 최근이라는 이유만으로 근거 없는 완료 주장을 채택하지 않는다.
- 상태/남은 작업은 해당 절을 고치고 이력은 날짜·작업자·근거를 붙여 마지막에 추가한다. 미완료를 완료로 바꾸거나 완료를 다시 열면 이유를 적는다. 옛 기록은 당시 사실임을 보존한다.
- 동시에 편집하지 않는다. 인계자는 실행 중 작업과 미커밋 상태를 남기고, 인수자는 최신 diff를 읽은 뒤 시작한다. 오래된 가이드 전체를 다시 써서 다른 AI의 내용을 지우지 않는다.
- 모델별 진입 파일은 이 기준 문서를 가리키는 얇은 연결로 유지한다. 별도의 복제된 로드맵을 만들지 않는다. 모델/도구를 알 수 없으면 루트 `AI_START_HERE.md`를 사용한다.
- 각 AI의 파일/브라우저/인증 접근은 별개다. 인계받지 않은 실행 결과·원자료·세션을 갖고 있다고 가정하지 않는다.

### Gemini에 넘기는 방법과 접근 범위

- **같은 로컬 폴더에서 Gemini CLI를 실행하는 경우:** 루트 `GEMINI.md`가 `AGENTS.md`와 이 가이드를 공식 `@./파일` 문법으로 import한다. 시작 후 `/memory show`로 실제로 로드된 문맥을 확인할 수 있고, 문서가 바뀌었으면 `/memory reload`로 다시 읽는다. 설치/로그인·개인 전역 설정 변경을 이 프로젝트 작업의 일부로 강제하지 않는다.
- **Gemini 웹 채팅 또는 다른 IDE:** 로컬 파일을 자동으로 읽는다고 가정하지 않는다. 가이드와 공통 지침을 첨부하거나 해당 프로젝트 폴더를 열어 읽도록 요청한다. 로컬에만 커밋한 변경은 GitHub를 통해 보는 AI에게 아직 보이지 않는다. 다른 컴퓨터라면 전달/동기화한 소스와 커밋부터 확인한다.
- **도구 접근:** 이 AI의 로그인 브라우저·파일 권한·연결 서비스가 다음 AI에게 자동 공유되는 것은 아니다. 가이드는 비밀번호/세션을 대신하지 않는다. 접근 불가를 자료 부재로 오해하지 않는다.
- **검증 가능한 인계:** 새 AI는 작업을 시작하기 전 제품 목적, 이번 범위, 보존할 데이터 규칙, 최신 코드/배포 차이, 다음 검증을 짧게 확인한다. 문서를 읽었다는 말만으로 모든 기능/계정 상태를 확인했다고 표시하지 않는다.

복사해서 사용할 시작 요청:

> 이 프로젝트의 GEMINI.md, AGENTS.md, docs/PROJECT_GUIDE.md를 먼저 읽고 현재 Git 변경과 마지막 인계 메모를 확인해. 사용자 기록을 보존하면서 P0의 다음 작업부터 이어가고, 개발 작업을 앱 할 일에 넣지 마. 작업 후 같은 가이드의 상태·남은 작업·검증·배포 여부를 갱신해. 접근할 수 없는 자료나 도구가 있으면 구분해.

### 변경과 검증

- 실제 개인 계정 수정은 사용자가 요청한 데이터 정리만 수행한다. 테스트는 `?sandbox&device=고유이름`에서 합성 자료로 한다. `localhost`와 공개 사이트는 저장소가 다르다.
- 수집한 자료는 먼저 검토 가능한 파일/차이로 정리하고 기존 기록을 보존하는 경로로 반영한다. 비밀키를 프론트에 넣지 않는다.
- 코드 변경은 의미 있는 회귀 검사와 `npm test`, `npm run build`, `git diff --check`. 문서만 바꾸면 링크/파일명/내용 일관성을 확인하고 코드 테스트를 실행한 척하지 않는다.
- 계정 변경, 중복 제출, 다른 창 편집, 실패/오프라인을 수정 대상과 관련 있는 범위에서 검사한다.

### 종료/인계

- 이 문서의 상태·남은 항목·마지막 인계 메모를 갱신한다. 완료한 것을 계속 대기 항목으로 남기지 않는다. 새 기능의 한계도 함께 적는다.
- 필요한 파일만 명시적으로 stage/commit. 미커밋 사용자 자료와 기존 미추적 파일은 섞지 않는다.
- 배포가 허용된 코드 묶음은 현재 워크플로를 확인한 뒤 push하고 Actions 성공까지 검증한다. `main` push는 자동 웹 배포다. 문서 커밋도 현재 워크플로에서는 배포를 트리거할 수 있다.
- 최종 답변은 무엇이 바뀌었고, 어떻게 확인했고, 무엇이 남았는지 짧게 설명한다. 마지막 인계 메모는 다른 AI가 대화 전체를 보지 않아도 시작할 수 있어야 한다.

## 8. 실행·배포와 개인정보

```sh
npm ci
npm run dev
npm test
npm run build
git diff --check
```

- 개발 기본 주소: `http://localhost:5173/`. 공개 주소: https://h3clo.github.io/hazeflow/
- 배포: `.github/workflows/pages.yml`, `main` push → 검사/빌드 → Pages. 작업 브랜치는 현재 상태를 먼저 확인하며 새 브랜치는 기본 `codex/` 접두사.
- 환경 변수 공개 URL/publishable key와 서버 비밀키를 구분한다. `.env.example` 참고. service-role/토스 secret/OpenAI 키를 `VITE_` 또는 공개 소스에 넣지 않는다.
- 자료 경로 기준은 로컬 `.private/data-locations.md`다. 사용자가 알려준 iCloud 보관 폴더와 주문/소득/소비세금 하위 폴더의 존재를 확인했다(2026-11-07). 경로 상세는 공개 가이드에 복제하지 않는다. 이 파일은 Git에서 제외되므로 다른 기기에서는 별도 인계가 필요하다.
- 개인 다운로드 자료는 프로젝트 밖 비공개 보관. **사용자가 주문내역 등 받은 자료 파일을 다른 곳으로 옮겼다. 프로젝트를 옮긴 것이 아니다.** 기존 `/Users/jini/Downloads/...` 경로가 유효하다고 가정하지 말고 실제 위치를 확인한다. 개인 파일을 찾지 못했다고 자료를 다시 전부 수집하지 않는다.
- 과거 `/tmp` 체크포인트는 임시 참고일 뿐 영구 인계 기준이 아니다. 필요한 기술 상태는 이 문서로 옮기되 개인 원자료는 옮기지 않는다.
- 현재 미추적 `docs/*preview.jpg`, `docs/sync-completion-*.jpg`, `shopping-batch-extractor.js`가 있다. 기존 작업 산출물이므로 임의 삭제/커밋하지 말고 실제 `git status`와 내용을 확인한다.

### 2026-11-07 · Cursor 리뷰 3개 수정 (Cursor)

- 목록의 삭제 버튼은 화면을 그릴 때의 기록을 버튼에 남긴다. 내부 데이터가 먼저 갱신되고 화면이 그대로여도, 그 버튼은 최신 기록과 다르면 지우지 않는다. 할 일·활동·즐겨찾기·자산 계정·일기 지우기가 이 경로를 쓴다.
- 중요 표시와 하루 마감은 버튼에 보인 값의 반대로 저장한다. 저장소가 이미 그 값이면 다시 뒤집지 않는다. 하루 마감은 일기 자동 저장 뒤에 버튼 값을 읽지 않고, 누르기 전에 보인 값을 쓴다.
- 일기 초안은 본문뿐 아니라 초안을 열 때 일기가 있었는지도 전달한다. 본문이 비어 있던 일기가 삭제되면 초안으로 다시 만들지 않는다. 메모·사진은 일기가 남아 있을 때 유지된다. 처음 쓰는 일기는 그대로 만들 수 있다.
- 재현 검사 3개는 수정 전에 실패했다. 화면 원본 대신 최신 제목을 골랐고, 중요 표시가 켜진 최신 값을 껐고, 빈 본문 일기의 존재 여부를 빠뜨렸다. 수정 후 전체 455 검사 통과.
- 합성 sandbox `review-guards`에서 입력칸에 포커스를 둔 채 저장소만 바꾼 뒤 화면에 남은 버튼을 눌렀다. 할 일 삭제는 거부되고 바뀐 제목이 남았다. 중요 표시는 저장소의 꺼진 값을 다시 켜지 않았다. 메모만 있던 일기를 지운 뒤 초안 저장은 거부되고 일기는 다시 생기지 않았다. 마감 전으로 보이던 버튼은 이미 마감된 일기를 다시 열지 않았고 메모도 남았다. 실제 계정은 쓰지 않았다. 아이폰 왕복은 확인하지 않았다. 웹에는 배포하지 않았다.
- 다음은 대기 중인 생활 기록 입력 개편이다. 이번 수정에서 화면 배치와 생활 입력은 바꾸지 않았다.
