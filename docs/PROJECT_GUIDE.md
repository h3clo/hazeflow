# Haze Flow 프로젝트 가이드 — 현재 작업 인덱스

> 기준일: 2026-11-08. 최신 사용자 지시와 실제 Git/코드 상태가 과거 문서보다 우선한다. 작업 시작에 필요한 내용만 읽고 상세는 관련 문서로 이동한다.

## 시작 순서

1. [AGENTS.md](../AGENTS.md)에서 데이터 보호·작업 범위·검증 규칙을 확인한다.
2. 아래 **현재 시작점**과 **작업 대기열**을 확인한다. 2주 실행 큐는 [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).
3. `git status --short`, 현재 브랜치·최근 커밋·관련 코드/테스트를 확인한다. GitHub에 없는 로컬 작업을 완료 또는 유실로 단정하지 않는다.
4. 해당 작업의 문서만 읽는다. 제품 원칙은 [PRODUCT_VISION.md](PRODUCT_VISION.md), 소비 데이터는 [payment-ledger-plan.md](payment-ledger-plan.md), 활동 UX 인계는 [UX_HANDOFF.md](UX_HANDOFF.md).
5. 작업 후 완료/미완료, 검증 근거, 배포 여부, 다음 시작점을 갱신한다. 긴 경과는 [handoff-history.md](handoff-history.md)에 남긴다.

## 제품 목표 — 모든 작업의 판단 기준

**기록 → 실제 변화 발견 → 자신에 대한 이해와 응원 → 일상으로 다시 돌아올 힘.** Haze Flow는 생산성 점수나 연속 달성률로 사용자를 평가하지 않는다. 기록이 없거나 성과가 낮은 날을 실패로 취급하지 않고, 근거 없는 칭찬도 만들지 않는다. 기능·UX 판단의 상세 기준은 [PRODUCT_VISION.md](PRODUCT_VISION.md)의 **Haze Flow를 만드는 근본적인 이유**를 따른다. 이 비전은 새로운 기능의 자동 구현 승인이 아니다.

## 짧거나 막연한 지시를 받았을 때

사용자가 “이어서”, “알아서”, “전부”, “완성해줘”라고 해도 **제품 비전과 기존 합의가 유지된다.** [AGENTS.md](../AGENTS.md)의 **방향을 잃지 않기 위한 작업 요청 해석 규칙**에 따라 현재 시작점의 작은 작업부터 실제 코드·Git 상태를 확인해 진행한다. 성과 압박 UI, 근거 없는 칭찬, 새 기능 무단 추가, 기존 기록 삭제·대량 재수집, 전체 UI 교체, 무단 배포를 자동 승인으로 해석하지 않는다. 큰 방향 변경만 사용자에게 확인하고, 기존 결정을 반복 질문하지 않는다.

## AI 주도 설계 방식

사용자가 불편함을 말하면 AI가 실제 사용 시나리오를 분석해 **권장 기본안과 검증 방법을 먼저 제시**한다. 반복적인 선택 질문으로 UX 결정을 떠넘기지 않는다. 기존 제품·데이터·UI 변경 경계는 유지한다. 상세 규칙은 [AGENTS.md](../AGENTS.md), 운동 합의는 [WORKOUT_UX.md](WORKOUT_UX.md).

## 현재 시작점

**큐 진행:** [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md)의 **Q0 → Q1…** 순서. 완료 기준 충족 시 즉시 다음. 푸시·배포·계정 데이터 변경·파괴적 Git·데이터 마이그레이션은 사전 승인 필요.

**Q0 · Git 합치기 (진행 중 → 완료 후 Q1)**
- 백업 브랜치 `backup/pre-q0-local-wip`에 로컬 UX WIP 보존. `origin/main` 12커밋은 fast-forward로 반영.
- 로컬에서 가져온 파일: `activity-classify.js`, `tests/activity-classify.test.js`, `app.js` classify import, `docs/UX_HANDOFF.md`, `docs/DEVELOPMENT_PLAN.md`.
- 완료 기준: 위 파일 보존 + `npm test`/`build` 기준선 기록. 강제 reset 없음.

**활동 기록 UX (Q1–Q2)**
- 분류기·테스트는 작업 트리에 있음. `captureView()` UI·이벤트·배포는 미완료. 순서: [UX_HANDOFF.md](UX_HANDOFF.md) 5번.
- 기존 활동·사진·운동·동기화 보존. `?sandbox&device=작업별이름` 사용.

**운동 UX (Q3-A/B/C, 2주 우선)**
- 자극 부위 교차 · 운동별 세트 수정 · 휴식 경과. 설계: [WORKOUT_UX.md](WORKOUT_UX.md). 전면 개편 아님.

**소비 데이터 (Q4)**
- 결제 원장 우선. Q4-A 조사 후 안전 단계 판정 → 승인된 단계만 Q4-B. **계정 반영·대량 재수집 금지(승인 전).** 과거 `.private` 보완은 자동 실행 대기열 아님.

**iCloud:** 별도 큐 I0–I3. 규모 미확인. 요청 없이 접근·변경하지 않음.

**배포 참고:** 문서상 코드 `41afcbe` / Actions `42287493954`. 합친 뒤 검사 숫자로 기준선을 다시 적는다.

## 작업 대기열

### P0 · 데이터 보존·실사용 오류
- [ ] iPhone 신규 사진 저장/재접속/Mac 표시 실기기 확인.
- [ ] iPhone ↔ Mac 활동 시작·종료·편집·충돌 및 오프라인 복귀 검증.
- [ ] 저장·삭제·토글·사진·계정 전환의 오래된 화면 충돌 보호 회귀 확인. 실제 계정 기록으로 시험하지 않는다.
- [ ] 좁은 화면·다크모드·입력 중 렌더 오류는 재현된 부분만 수정.

### P1 · 활동 기록 입력 UX
- [ ] 한 줄 입력, 규칙 기반 카테고리 추천, 사용자 선택 우선, 활동 시작/짧은 기록, 추가 설정 접기/펼치기 완성 (Q1–Q2).
- [ ] 기존 저장·동기화·운동 파서 회귀 검증 및 화면 확인. 구현/검사/배포/실기기 검증을 구분.

### P1 · 운동 기록 실사용 오류 및 입력 흐름 (설계 합의, 코드 미검증)
- [ ] 자극 부위 교차 재현·원인 구분·최소 수정 (Q3-A).
- [ ] 운동별 독립 항목·목표/실제 세트 수정·원문 보존 (Q3-B). 스키마 파급 시 근거·예상 시간 후 판정.
- [ ] 세트 완료 시 휴식 경과, 일괄 기록 시 미시작 (Q3-C). 백그라운드는 검증 전 미보장.
- [ ] 헬스장 조작 수·재입력 감소, 운동별 자극 부위 독립성, 모바일 실제 사용성. **전면 개편 자동 승인 아님.**

### P1 · 소비 데이터 구조 전환
- [ ] 기존 코드와 [payment-ledger-plan.md](payment-ledger-plan.md) 매핑·안전 단계 판정 (Q4-A).
- [ ] 판정·승인된 단계만 구현 (Q4-B). **승인 전 실제 계정 데이터 변경 금지.**
- [ ] 은행·카드·현금영수증 출처별 검토, 중복/환불/다대다 연결, 미연결 결제 확인 흐름.
- [ ] 기존 쇼핑몰 자료 연결·마이그레이션 계획은 승인 후. 과거 보완 JSON 자동 적용 금지.

### P2 · 기존 기능 완성
- [ ] 건강/식단/인바디 비교 및 추정·누락 표시.
- [ ] 공부 일시정지/재개, Obsidian/블로그 연결 실제 동작 검증.
- [ ] 결제와 연결된 검증 상품만 가격·구매 간격·단위가격 분석.
- [ ] 가족·자산·연간 소득/세금 자료의 중복 합산 방지 및 검증.

### P3 · 이후 검토
- [ ] 알림, 외부 AI, 설치형 앱/건강 연동은 별도 승인과 보안·비용 검토 후 착수.
