# 요청·제안 기능 대조 (2026-11-01)

## 반영된 핵심 흐름

- 오늘: 일정·실제 활동 시간표, 시작/종료 수정, 진행 중 표시, 짧은 메모, 사진
- 계획: 월간 캘린더, 기한 없는/오늘/미래 할 일, 중요 표시, 반복 루틴, 올해 목표·버킷리스트
- 대시보드: 포스트잇+일정 캘린더, 헤더 진입, 뒤로가기·닫기 복귀
- 기록: 일기·기록 기반 일기 초안, 과거 비교, 주간 회고, MD/이미지/사진 포함 백업
- 운동: 묶음 종목, 지난 기록·즐겨찾기, 예상 근육/직접 느낀 부위 그림 선택, 체감·힘듦, 마지막 운동 경과 시간
- 몸: 신체 정보, 인바디 사진 OCR 확인·CSV 가져오기, 측정 사이 운동·식사 회고
- 자산: 수동 잔액·보유 종목, 본인 계정 일별 토스 평가액, 코인 시세, 제공자 차트
- 계정: 이메일·비밀번호, 로그인 유지, 기존 계정 동기화

## 이번 추가분

- 쇼핑 주문 한 건의 원문 붙여넣기 → 값 제안 → 확인 저장. 주문 원문은 저장하지 않고 거래·주문번호·상품명만 보관한다. 동일 주문번호 및 기존 거래의 중복을 확인한다. 취소·환불 완료 주문은 새 지출로 추가하지 않는다.
- 복합 결제: 카드·온누리·포인트 등 2~6개 수단과 금액. 합계 일치 검증, 식사 연결 거래의 수정에서도 지원. 지출은 총액 한 번만 합산한다. CSV/JSON에 상세 보존.
- 식사 영양정보: 열량·단백질·탄수화물·지방 중 확인한 값 입력, 즐겨찾기 보관·불러오기, 절반/2배 조절, 초안 복구. 몸 변화/주간 회고에서 입력 범위와 합계 표시. 미입력과 0은 구분한다.

- 앱 공유로 영수증 가져오기·푸시 알림·배포 가능한 네이티브 앱: 네이티브 기반은 있으나 iOS 개발 약관 승인, 서명 및 실기기 검증 등이 남았다. 자동으로 약관에 동의하거나 인증정보를 바꾸지 않는다.
- 아이폰 실제 촬영 문제: 사진 선택·처리/오류 안내는 구현됐으나 실제 기기에서의 최신 재검증이 필요하다.
- 외부 AI 일기: 로컬 개발 서버 키 설정 방식은 있으나 GitHub Pages 자체에는 비공개 AI API 서버가 없다. 기록 기반 로컬 초안은 사용 가능하다.

## 2026-11-03 · 후속 반영과 실제 데이터 상태

아래 공부·차트·동기화 변경은 fb2ffe4로 배포했다. 이후 추가한 연간 소득 자료 기능은 별도로 검증 중이다.

- 공부: 시작·마침, 사용자 과목 관리, 한 줄 결과/다음 행동, 질문 복습, Obsidian용 MD/새 노트 요청, 블로그 초안·링크 연결. 외부 편집 내용의 양방향 동기화나 블로그 발행은 하지 않는다.
- 차트: 월별 일일 지출과 분류 비중, 인바디 네 항목의 개별 추이, 최근 7일 공부와 과목 비중. 단위·기간·원자료 표를 함께 제공한다.
- 소비 패턴: 품목·단위를 선택해 전체 구매일의 단위가격과 구매일 간격을 비교한다. 같은 날의 상품 금액/총 수량으로 수량 가중 단가를 계산한다. 구매일 사이 간격은 실제 소진 기간을 뜻하지 않으며, 할인·구성·판매처 차이가 가격에 포함된다. 상품별 확인 금액 없이 주문 총액을 배분하지 않는다.
- 공부 요약과 차트는 같은 날짜별 배분을 사용한다. 자정을 넘긴 공부는 각 날짜에 배분하고, 주 시작일보다 먼저 시작한 구간도 해당 주의 실제 구간만 포함한다. 미래 날짜 조회에서도 오늘까지 집계한다.
- 쇼핑 분류: 미분류 주문의 상품명 기반 제안을 확인 저장한다. 대표 상품만 있는 복수 상품 주문과 여러 분류가 섞인 주문은 자동 선택하지 않는다. 다른 기기에서 바뀐 거래는 건너뛴다.
- 대시보드: 포스트잇 중요 배지와 중요/수정/삭제 버튼, 다크 캘린더 배경/글자 수정. 합성 데이터의 중요 할 일 및 일정으로 다크 화면 확인.
- 자동 동기화는 기존에도 저장 후/실시간/30초/화면 복귀 시 동작했다. 전체 데이터를 매번 내려받지 않고 변경 버전을 확인해 바뀐 기록만 받도록 개선했다. 기기가 실제로 닫혀 있을 때 백그라운드 실행을 보장하는 기능은 아니다.

실제 계정에는 이전 검토 완료 주문 115건이 들어가 있고, 별도로 모은 쿠팡 카드 주문 117건은 아직 취소·부분 결제 검토와 가져오기가 남아 있다. 나머지 쿠팡 연도별 영수증 수집도 완료되지 않았다. 제공된 인바디 CSV 8회는 파서 호환 확인만 했고 실제 계정에 넣지 않았다. 상품별 수량·금액이 없는 주문은 소비 패턴 차트의 상품 분석에 포함되지 않는다. 수집 완료/가져오기 완료/상품별 분석 가능은 서로 다른 상태다.

검증 화면은 실제 사용자 자료와 분리된 sandbox의 합성 주문 5건으로 만들었다. CSV 가져오기, 품목 선택, 날짜 간격과 단가, 다크 화면을 확인했다. 실제 아이폰 촬영·기기 간 왕복·외부 Obsidian 노트 생성은 이번 검증에 포함하지 않는다.

## 2026-11-05 · 전체 요청 재대조

이전 날짜의 데이터 건수는 당시 진행 상황이며 전체 수집 완료를 의미하지 않는다.

### 최근 배포 완료

- 품목별 할인 후 가격·총 수량으로 소비 분류, 단가 추이, 구매일 간격을 계산한다. 원자료가 없는 상품 가격은 주문 총액으로 나누지 않는다.
- 선·막대·원형 차트의 마우스/터치/키보드 수치 확인. 구매 단가와 실제 결제 합계·총 수량을 함께 표시한다.
- 주문 붙여넣기의 결제 시간 제안·수정·저장. 시각이 없는 자료에 현재 시각을 임의로 채우지 않는다.
- 같은 날의 반복 계획을 예정 시각 전에 시작할 수 있고, 오늘의 흐름에서 바로 시작한다. 예정 시각과 실제 시작은 분리한다.
- 상품 정리·거래 수정 중 다른 기기에서 바뀐 기록을 오래된 화면으로 덮어쓰지 않도록 검사한다.
- 변경 버전 목록과 상세 응답이 맞지 않으면 동기화 완료로 표시하지 않고 재시도한다. 충돌 기록 외의 새 활동은 별도로 전송한다.

### 남은 실제 자료 작업

- 판매처 요약만 있거나 할인·반품 구분이 부족한 주문의 상품별 자료 확인.
- 근거 자료에 있는 기존 거래 시각을 빈 시간에만 보완. 수동 시간·금액·상품 상세·생활 기록 보존.
- 홈택스·위택스·각 쇼핑몰의 수집 가능 범위와 실제 저장 범위를 대조. 모든 연도·모든 가족 자료를 수집 완료했다고 표현하지 않는다.

### 아직 완성되지 않은 큰 기능

- 쇼핑몰 새 주문의 주기적 갱신과 취소·부분 환불의 안전한 연결.
- 음식·제품·먹은 양을 확인하는 영양 데이터 연동과 자동 입력.
- 유산소/혼합 운동 소모량 추정 확대와 근육별 회복 참고 정보. 실제 회복 완료를 단정하지 않는다.
- 비공개 서버를 통한 외부 AI 일기. 현재 기록 기반 초안과 구분.
- iPhone/iPad/Android 앱 서명·배포, 실기기 촬영·앱 복귀·동기화 검증, 푸시/공유 기능.
- 가족 데이터의 수집 범위·공동 지출·실제 부담자 구분을 실제 자료로 검증.
- 공부→Obsidian 노트 생성 및 블로그 연결을 사용자의 실제 환경에서 확인. 현재 파일/URI/초안 기능과 실제 생성·발행 성공은 구분.

구현·자동 검사 통과·배포·실기기 확인·실제 자료 수집 완료는 별개의 상태다.

### 오늘의집 가져오기 후속

오늘의집을 주문 붙여넣기·CSV/XLSX 표·화면 추출 도구의 쇼핑몰 목록에 추가했다. 원문 파서와 파일 검토 흐름은 합성 자료로 검사했다. 실제 주문 화면에서의 추출 성공·전체 기간 수집·자동 수집 완료를 뜻하지 않는다.

네이버/오늘의집의 같은 날짜·금액 거래는 중복 **후보**로 안내한다. 파일에서는 기본 선택을 해제하고, 한 건 붙여넣기에서는 기존 거래와 다른 구매인지 확인해야 한다. 날짜·금액만으로 거래를 자동 병합하지 않는다. 한 건 붙여넣기에서 사용자가 같은 구매임을 확인하고 기존 결제에 다른 쇼핑몰 주문번호를 연결할 수 있다. 금액·원문·상품 상세는 유지하고 연결 이후에는 파일 가져오기와 가계부 CSV에서도 중복을 인식한다. 파일 검토 화면에서도 각 중복 후보의 기존 결제를 선택해 주문번호를 연결할 수 있다. 여러 건을 근거 없이 일괄 병합하지 않는다.

## 2026-11-06 · 동기화 실기기 확인 및 영양정보 입력 보완

- 변경 기록 조회에서 JSON 형식 키의 따옴표·역슬래시가 잘못 전달되는 문제를 수정했다. 변경 상세가 누락되면 전체 조회로 한 번 복구하고 버전을 다시 검증한다. 불완전한 응답을 완료로 표시하지 않는다.
- 0fe92ee 배포 후 사용자가 iPhone 홈화면 앱의 현재 버전과 ‘동기화 완료’를 확인했다. 실제 카메라 신규 촬영·다른 기기 표시까지 이번 답변으로 검증된 것은 아니다.
- 제품 영양정보 문구 붙여넣기에서 명시된 열량(kcal)·단백질/탄수화물/지방(g)을 읽어 입력칸에 채운다. 읽지 못한 항목은 기존 값을 유지하고 같은 항목의 서로 다른 값은 거부한다. 음식명 기반 추정·사진 자동 인식·섭취량 자동 판단은 하지 않는다. 기존 절반/2배 조절과 즐겨찾기를 함께 사용할 수 있다.
- 합성 식사의 문구 읽기 → 절반 조절 → 저장 → 새로고침 → 수정 화면에서 값 유지 확인. 자동 검사 349개와 빌드 통과.

### 쇼핑 파일의 중복 후보 연결 보완

- CSV/XLSX·표 붙여넣기의 네이버/오늘의집 중복 후보에 기존 결제 선택과 주문번호 연결을 추가했다. 실제 결제금액 확인을 체크하고 같은 구매임을 확인한 건만 연결한다. 기존 금액·분류·사진·상품 정보는 유지하며 되돌리기를 제공한다.
- 검토 이후 기존 결제가 변경되면 저장을 거부한다. 날짜·숫자 금액이 같아도 통화가 다르면 후보에 포함하지 않는다.
- 합성 자료로 기존 5,000원 거래 가져오기 → 오늘의집 주문 연결 → 새로고침 후 거래 1건·합계 5,000원·연결 주문번호 유지 확인. 실제 사용자 거래는 수정하지 않았다.

### 쇼핑몰별 자료 범위와 정리할 주문

소비 패턴에 접어서 볼 수 있는 ‘쇼핑몰별 기록 범위’를 추가했다. 선택한 사용 범위의 전체 기간을 대상으로 쇼핑몰별 기록 지출 차트, 첫·마지막 구매일, 주문 수, 상품별 금액 정리 비율과 가격 확인 전 금액을 표시한다. 연결 주문은 원래 결제 쇼핑몰에 한 번만 집계한다. 저장된 구매일 범위는 해당 기간 전체를 수집했다는 뜻이 아니다.

각 쇼핑몰의 가격 확인할 주문 목록에서 상품 정보 정리를 바로 열 수 있다. 상품 정보 창의 ‘미배분’ 문구는 ‘가격 확인 전’으로 통일했다. 배송비·할인·반품 등 차액을 상품 가격으로 추정해서 나누지 않는다. 합성 거래로 목록→상품 편집 진입을 확인했고 기존 자료를 수정하지 않았다.

웹 계정 화면에 ‘앱 새로 불러오기’를 추가했다. 동기화를 먼저 시도하고 현재 전송 대기·사진 처리·충돌이 없는 동기화 완료 상태에서만 같은 주소에 최신 요청 값을 붙여 다시 연다. 로그인·기기 저장소를 지우지 않는다. 별도 설치한 네이티브 앱에는 웹 업데이트 버튼을 표시하지 않는다. 전체 검사 354개와 빌드 통과.
