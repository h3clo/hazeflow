# Live Activities 첫 구현 PR 범위

기준: 2026-11-11. **첫 구현은 [PR #46](https://github.com/h3clo/hazeflow/pull/46).** 잠금 화면의 실제 배치와 iPhone 13 확인은 아직이다. Apple Watch, 원격 푸시, Dynamic Island 전용 레이아웃은 시작하지 않는다. ActivityKit이 요구하는 `dynamicIsland` 클로저는 같은 제목과 시스템 타이머만 반복한다.

기존 활동 2.0과 Supabase 동기화를 다시 만들지 않는다. 진행 중 기록은 종료 시각이 비어 있는 활동이고, 대표 활동은 `preferences.activityUi`다. 네이티브는 그 값을 받아 잠금 화면에 보여줄 뿐이다.

## 첫 PR에서 할 일

1. iOS 위젯 확장 하나를 추가한다. 속성은 제목, 시작 시각, 분류, 대표 여부만 둔다.
2. 앱 안의 Swift가 ActivityKit으로 시작하고 갱신하고 끝낸다. JS는 기존 활동 저장이 성공한 뒤에 그 결과만 넘긴다.
3. 활동을 시작하면 대표 활동 Live Activity를 연다. 이미 떠 있으면 새로 만들지 않고 내용을 바꾼다.
4. 진행 중이 여러 개면 Live Activity에는 대표 하나만 보여 준다. 대표를 바꾸면 같은 활동을 갱신한다.
5. 대표 활동을 끝내면, 다른 진행 중이 있으면 그 대표로 바꾸고 없으면 Live Activity를 끝낸다.
6. 앱을 다시 열면 JS가 로컬 진행 중·대표를 읽고, 네이티브 표시와 다르면 맞춘다. 저장의 원본은 지금처럼 로컬 기록과 동기화 엔진이다.
7. 원격 푸시 갱신, App Group으로 기록을 복사하는 두 번째 저장소, Watch 전달은 넣지 않는다.

## 잠금 화면과 Dynamic Island

- 잠금 화면 Live Activity는 구현 대상이다.
- Dynamic Island는 기기가 지원할 때만 같은 활동의 압축 표시를 쓴다. iPhone 13에는 Dynamic Island가 없으므로 잠금 화면만 해당한다.
- 무료 Personal Team으로 **앱이 직접** 시작하고 갱신하는 것까지를 범위로 한다. 푸시로 잠금 화면을 갱신하는 entitlement는 유료 프로그램이 필요하므로 제외한다. 무료 서명은 약 7일이면 다시 설치가 필요하다.

## 자동 테스트와 실기기

- JS 단위 테스트: 진행 중 목록과 대표 id로 네이티브에 넘길 페이로드를 고른다. 대표가 없으면 가장 최근 진행 중을 고르지 않고, 이미 정한 대표 규칙을 재사용한다.
- 시뮬레이터: 활동 시작·대표 변경·종료 호출이 예외 없이 끝나는지만 확인한다. 잠금 화면의 실제 배치는 보장하지 않는다.
- 실기기에서만 볼 것: 잠금 화면 문구, Dynamic Island, 앱을 죽인 뒤의 표시 유지, 무료 서명 만료.

## 하지 않을 것

- 원격 푸시 갱신, Watch, 전용 Dynamic Island UI
- 실사용 계정 데이터로 시험
- 웹 활동 화면을 네이티브로 다시 작성
- 활동 기록·Supabase 스키마 변경
