# 알림 확장 계획

구현한 범위와 아직 미구현인 기능을 구분한다.

## 구현한 범위

- 헤더 알림 설정. 일정·할 일·루틴·공부 복습을 선택하고 미리 알릴 시간을 정한다.
- 화면이 보이는 동안 15초 간격으로 확인한다. 최근 5분 안의 예약만 표시하며 오래된 알림을 한꺼번에 보내지 않는다.
- IndexedDB에 기기별 설정과 중복 확인 내역을 저장한다. 여러 창이 같은 알림을 동시에 보내지 않도록 트랜잭션으로 확인한다.
- 지원되는 환경에서 사용자가 명시적으로 권한을 허용하면 서비스 워커로 기기 알림도 표시한다. 이 예약 확인도 화면이 보일 때만 실행된다.
- iPhone 앱은 같은 알림 설정을 로컬 알림으로 예약한다. 기본값은 꺼짐이고, 권한은 기기 알림 허용을 눌렀을 때만 요청한다. 활동 시작만으로는 알림을 만들지 않는다.
- 완료·시작·일정 시간 변경을 반영하며 기한 없는 할 일은 알리지 않는다.

## 아직 미구현


- 일반 웹 푸시: 일정·할 일·공부 복습 알림. 서비스 워커, 사용자 동작에 따른 권한 요청, 서버 예약 전송, 계정별 구독 관리가 필요하다.
- iOS 실시간 현황: 과목·경과 시간·일시정지·재개·종료. 웹 푸시와 별개이며 설치형 앱의 ActivityKit/위젯 확장과 App Intent 연결이 필요하다.
- Android 진행 중 알림: 타이머 표시 및 액션 버튼. 설치형 앱의 알림/서비스 수명주기와 연결한다.
- 일반 기록의 오프라인 저장과 오프라인에서 앱을 새로 여는 기능은 별개다. 화면 파일의 오프라인 캐싱은 아직 구현하지 않았다.

일시정지 기능은 휴식 구간을 별도로 보관하고, 표시 시간과 최종 공부 시간이 일치하도록 구현한다. 여러 기기에서 같은 세션을 제어할 때 중복 시작·종료를 방지해야 한다. 현재 기록 저장소 이전 배포에 알림 기능이 포함되었다고 표시하지 않는다.
