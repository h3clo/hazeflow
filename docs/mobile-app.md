# Haze Flow 앱 전환 준비

## 구성

기존 Vite 웹 + Capacitor 8. 아이폰/안드로이드/웹은 같은 저장 형식과 Supabase 계정을 사용한다. 앱에는 빌드된 화면을 넣으며 GitHub Pages를 띄우는 `server.url` 설정을 사용하지 않는다. 웹과 앱의 세션은 별도지만 같은 이메일로 로그인하면 같은 서버 기록을 이어쓴다.

## 이메일·비밀번호 로그인

- 이메일을 아이디로 사용. 새 가입은 비밀번호 8자 이상 + 확인 입력.
- 기존 이메일 링크 계정도 그대로 사용. 이미 로그인한 기기에서는 `내 계정 → 비밀번호 설정·변경`에서 `updateUser`로 비밀번호만 추가한다.
- 로그인할 수 없으면 같은 이메일로 `비밀번호 설정·재설정` 메일을 요청한다. 확인 링크를 열면 새 비밀번호 입력창을 표시한다.
- 매번 메일을 받지 않는다. 최초 가입 이메일 확인/비밀번호 분실 시에만 메일이 필요하다. 무료 Supabase 기본 발송은 수신 주소·발송량 제한이 있으며 본인 계정으로 실사용 검증이 필요하다.
- 비밀번호와 확인 입력은 Supabase로만 전송하며 앱 상태/기록/내보내기에 저장하지 않는다. 세션은 기존 로그인 유지 선택에 따라 localStorage/sessionStorage 사용.
- OTP 템플릿 변경/SMTP 연결/유료 업그레이드는 하지 않았다. 인증번호 방식은 사용자 선택에 따라 제외했다.

## 앱 빌드

Node 22 이상에서 `npm ci` 후 `.env.local`에 기존 **공개** Supabase URL/publishable key를 설정한다. service-role/토스 secret을 넣지 않는다.

- `npm run app:sync`: OCR 준비 → 앱용 웹 빌드(`/` 경로) → 아이폰·안드로이드에 복사.
- `npm run app:ios`: Xcode 프로젝트 열기.
- `npm run app:android`: Android Studio 프로젝트 열기.
- `npm run build`: 기존 웹 배포. GitHub Actions에서는 `/hazeflow/` 경로 유지.

## 인증 링크로 앱 복귀

두 플랫폼에서 `io.h3clo.hazeflow://auth/callback` 스킴을 등록했다. 앱에서 가입/재설정 메일을 요청하면 이 URL로 돌아오고 PKCE 코드만 세션으로 교환한다. 정확한 스킴·호스트·경로만 허용한다. Supabase URL Configuration의 Redirect URLs에 이 **정확한 URL**을 등록하고 총 5개 허용 URL을 확인했다. 넓은 와일드카드 설정은 사용하지 않는다. 웹의 기존 허용 URL은 유지한다.

## 네이티브 동작

- 앱 복귀 시 인증 토큰 갱신/동기화 재개, 백그라운드에서 갱신 중단.
- Android 뒤로가기: 열린 창 닫기 → 화이트보드 목록 → 오늘 → 앱 최소화.
- iOS 사진/카메라 사용 설명, 안전 영역 설정. 사진 입력은 기존 파일 선택기를 유지.
- 앱 세션의 OS 보안 저장소/생체 인증은 아직 추가하지 않았다.
- 브라우저 다운로드를 네이티브 공유/파일 저장으로 연결하는 작업, 실기기 카메라·HEIC·인증 링크 복귀 검증은 앱 실사용 전 추가로 필요하다.

## 검증 제한

웹/앱 웹 자산 빌드와 Capacitor 두 플랫폼 동기화 성공. 실제 이메일을 발송하지 않는 분리 QA로 로그인/잘못된 비밀번호/같은 계정 동기화/비밀번호 설정 UI를 검증한다. 실제 본인 비밀번호 입력·설정·변경은 사용자가 직접 한다.

- iOS 컴파일은 미동의 Xcode/SDK 약관에서 중단됨. 사용자가 Xcode를 한 번 열어 약관·초기 설정을 완료해야 한다. 자동 동의하지 않았다.
- Android 컴파일은 로컬 JDK/SDK 미설치로 미실행. Android Studio를 설치하면 포함된 도구로 빌드 가능.
- 스토어 등록·유료 개발자 가입·서명/배포는 진행하지 않았다.

## 토스 조회 연동

공식 API 범위는 확인했지만 비용/이용 조건과 사용자 키 설정 전에는 활성화하지 않는다. 개인 조회 서버에서 인증 사용자만 보유 종목·수량·환율·현재가를 조회하는 구조가 필요하다. 고정 IP 요구도 확인해야 한다. 앱/공개 저장소에 토스 secret을 넣지 않으며 주문 기능은 구현하지 않는다.
