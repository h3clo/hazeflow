# 결제 원장 중심 소비 데이터 수집·대조 설계

> 상태: **새 제품 방향 / 미구현**. 기존 쇼핑몰 파일 가져오기 기능이 이 설계를 구현했다는 뜻이 아니다. 실제 자료와 소스 확인 없이 완료 처리하지 않는다.

## 목적과 기준

**은행·카드사·현금영수증의 확인 가능한 결제·환불 내역을 먼저 수집하고, 쇼핑몰의 주문·상품 자료를 그 결제에 연결한다.** 쇼핑몰 주문 목록을 전체 지출의 기준으로 삼지 않는다. 품목 정보가 없는 결제도 지출 원장에 남는다.

- 카드 승인과 매입/청구, 은행 출금, 현금영수증은 서로 다른 증빙일 수 있다. 동일 소비의 복수 증빙을 별도 지출로 합산하지 않는다.
- 계좌이체·카드대금 납부·충전·환불·취소·포인트 사용은 지출/자금 이동/조정 성격을 구분한다. 결제 내역이 있다고 실제 구매가 확정됐다고 단정하지 않는다.
- 결제 기록(금액·일시·수단·거래 식별자·상태)과 주문 기록(판매처·주문번호·상품·수량·가격·배송비·할인)은 **별도 원본**으로 보존하고 연결 관계를 만든다.
- 주문 1건 ↔ 결제 여러 건, 결제 1건 ↔ 주문 여러 건, 부분 취소/환불, 포인트·쿠폰·복합결제를 허용한다. 금액/날짜만 같다는 이유로 자동 확정하지 않는다.
- 원본의 출처·수집 시각·원본 식별자·검증 상태를 남기고, 사용자가 직접 수정한 연결/분류/금액을 임의로 덮어쓰지 않는다.

## 목표 작업 순서

1. **결제 원장 확보:** 사용자가 접근 가능한 은행 거래내역, 카드사 이용내역, 현금영수증 내역을 기간별로 수집한다. 각 출처의 제공 범위와 누락 기간을 기록한다. 공식 내보내기·사용자 제공 파일 등 허용된 방법을 우선하며, 자동 연결이 가능하다고 가정하지 않는다.
2. **중복·정산 대조:** 승인/취소/매입, 은행 출금과 카드대금 납부, 현금영수증, 환불·부분환불, 복합결제 등을 대조해 지출 중복 집계를 막는다. 불확실한 것은 '검토 필요'로 둔다.
3. **기존 쇼핑몰 자료 연결:** 네이버·쿠팡·지그재그·11번가·G마켓 등 현재 접근 가능한 주문/상품 상세를 수집해 결제 원장과 연결한다. 판매처와 결제처 이름이 다를 수 있으므로 단순 문자열 일치만 사용하지 않는다.
4. **미연결 결제 목록 작성:** 결제는 확인되지만 주문/상품 정보를 찾지 못한 거래를 날짜·금액·결제처·연결 상태로 보여준다. 주문 자료가 부족하다고 결제 자체를 버리거나 임의 상품을 생성하지 않는다.
5. **사용자에게 추가 구매처 확인 요청:** 기존 쇼핑몰에서 찾지 못한 결제에 대해서만 '어느 쇼핑몰/매장에서 구매했는지' 확인을 요청한다. 사용자가 새 쇼핑몰을 알려주거나 자료를 제공하면 **그 쇼핑몰만** 추가 수집·대조한다. 사용자 확인 없이 쇼핑몰 범위를 끝없이 확장하지 않는다.
6. **품목 분석:** 검증된 연결만 상품별 가격·수량·단위·구매 간격 분석에 사용한다. 미연결 결제는 총지출에는 적절한 분류로 포함하되 품목 분석에는 임의 배분하지 않는다.

## 안전한 구현·마이그레이션 원칙

- 기존 쇼핑몰 중심 수집/가져오기 코드는 **레거시 기능**이다. 새 결제 중심 흐름이 검증되기 전에는 기존 기록, 연결, 상품 상세, 수동 분류를 삭제하거나 일괄 재생성하지 않는다.
- 기존 결제/주문 데이터는 백업 후 식별자·중복·환불·연결 상태를 점검하여 단계적으로 전환한다. 기존 쇼핑몰 데이터를 원장으로 무조건 승격하지 않는다.
- 수집 → 정규화 → 후보 연결 → 사용자 검토 → 반영을 분리한다. 원본/미리보기만으로 실제 계정 기록을 수정하지 않는다.
- 카드·계좌·현금영수증의 상세 개인정보, 인증정보, 영수증 원문은 공개 Git 저장소에 커밋하지 않는다. 비공개 파일 경로는 로컬 `.private/data-locations.md`에서만 관리한다.
- 은행/카드/현금영수증 자료에 접근할 수 없으면 접근 불가와 필요한 사용자 행동을 명확히 남긴다. 수집되지 않은 내역을 없는 소비라고 판단하지 않는다.
- 작업 완료 기준: (a) 동일 소비의 중복 증빙 미합산, (b) 부분 취소/환불과 복합결제, (c) 일대다·다대일 연결, (d) 미연결 목록 및 사용자 확인, (e) 기존 데이터 보존을 테스트하고 실제 반영/배포/기기 검증을 별도로 보고한다.
