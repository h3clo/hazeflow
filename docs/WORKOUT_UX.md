# 운동 기록 UX — 실제 사용 흐름 기준 (설계, 미구현)

> 2026-11-08 사용자와 합의한 제품 방향. 기존 기능/데이터 구조와 구현 상태는 코드 조사 전까지 단정하지 않는다.

## 관찰된 사용 시나리오와 문제

- 헬스장 도착 후 스트레칭하고, 빈 기구와 컨디션에 따라 그때그때 운동을 정한다. 정해진 순서 강제는 부적절하다.
- `러닝머신 5 5`로 워밍업하고, `어시스트 풀업 55 15 3`으로 목표를 적는다. 실제로 15회를 못 하면 같은 입력창의 긴 운동 텍스트를 다시 수정해 `어시스트 풀업 55 15 2 어시스트 풀업 55 12 1`처럼 고친다.
- 한 입력에 여러 운동을 넣어 기록했을 때 어시스트 풀업·체스트프레스에서 선택한 상체 자극 부위가 런지의 하체 자극 선택 화면에도 체크된 것으로 보였다. **실제 저장 데이터 혼합인지 UI 선택 상태 공유인지는 미확인**. 재현 및 저장·재진입 검사 필요.
- 휴식 타이머가 기술적으로 고장 난 것으로 확인된 것은 아니다. 현재 기록 방식이 세트 완료 시점을 표현하지 못해 **실사용에서 타이머를 활용하기 어렵다**는 문제다.
- 운동 중 휴대폰 조작을 최소화하고 싶지만, 어떤 날은 세트마다, 어떤 날은 운동을 마친 뒤 몰아서 기록한다. 사용자가 두 방식을 미리 선택하도록 강제하지 않는다.

## 결정된 UX 원칙

1. **입력창 하나, 운동 항목은 독립적으로.** `운동명 kg 횟수 세트`, `러닝머신 속도 분` 등 기존 한 줄 문법을 유지한다. 여러 운동을 한 번에 붙여 넣는 기존 기록도 유실 없이 읽을 수 있어야 한다. 새 운동 추가는 기존 긴 텍스트 전체를 다시 편집하지 않아도 된다.
2. **운동 세션 → 운동 항목 → 세트**의 개념을 분리한다. 실제 데이터 스키마 변경 여부는 코드 확인 후 결정한다. 자극 부위는 운동 항목별로 독립 관리하고 예상 부위와 실제 체감 부위를 혼동하지 않는다.
3. **목표와 실제 수행 구분.** 목표 `55 15 3`은 보존하고, 수행 중 3세트째 12회를 했다면 해당 세트만 수정한다. 같은 횟수를 묶어 입력하든 개별 수정하든 최종 세트별 결과는 동일하게 보존한다. 기존 원문도 보존한다.
4. **기록 방식 전환을 강요하지 않는다.** 세트별 완료와 운동 종료 후 일괄 입력을 같은 운동 항목에서 자유롭게 사용한다. 일괄 완료/과거 입력은 타이머를 자동 시작하지 않는다.
5. **휴식은 별도 설정 화면보다 자연스러운 흐름.** 세트 완료를 누르면 경과 시간 표시를 시작하고 다음 세트 시작으로 종료한다. 고정 카운트다운·재촉을 기본으로 강요하지 않는다. 알림/진동은 선택 기능이며 브라우저 백그라운드 동작을 실제 검증하기 전에는 보장하지 않는다. 세트 완료 취소·수정 시 휴식 상태도 일관되게 처리한다.
6. **상황별 화면은 같은 기록을 공유.** 운동 중에는 현재 운동·세트·휴식만 간결하게, 사후 편집에는 일괄 입력·수정을, 회고에는 실제 기록 비교를 보여준다. 별도 화면 신설/큰 재배치는 코드 검토와 범위 합의 후 단계적으로 진행한다.
7. **정확한 비교.** 어시스트 풀업의 55kg은 보조 중량이므로 일반 중량과 같은 방향으로 성장을 해석하지 않는다. 일반 러닝머신은 경사 입력을 요구하지 않는다. 미입력/미완료를 실제 수행으로 확정하지 않는다.

## 우선 구현/검증 시나리오

1. **원인 조사:** 한 기록에 어시스트 풀업·체스트프레스·런지를 입력하고 각각 자극 부위를 달리 선택한다. 다른 운동으로 전환/저장/재진입/기기 동기화 시 체크 UI와 저장값을 별도로 확인한다.
2. **기존 기록 보존:** 단일 운동, 여러 운동이 이어진 원문, 0kg, 보조 중량, 유산소, 운동별 서로 다른 세트 횟수, 사진·활동 시간·기존 동기화 데이터를 회귀 검사한다.
3. **작은 구현:** 운동별 독립 선택 상태 및 기존 파서의 실제 오류부터 고친다. 그다음 한 줄 추가→운동별 카드/세트 편집→세트 완료/일괄 기록→휴식 경과 측정 순서로 검증 가능한 작은 묶음으로 진행한다.
4. **휴식 시나리오:** 세트 완료 시 시작, 다음 세트 시작 시 종료, 일괄 입력 시 미시작, 취소·화면 이탈·복귀·백그라운드 제한 확인. 화면 밖 정확도는 종료 시각 기반으로 설계·검증한다.
5. **사용성 기준:** 운동기구 앞에서 다음 운동을 추가할 때 기존 기록 전체를 수정할 필요가 없는가? 실제 횟수가 달라져도 한 세트만 고치면 되는가? 다른 운동의 자극 부위가 섞이지 않는가? 운동 중 불필요한 타이머 조작을 요구하지 않는가?

## 범위 경계

- 본 문서는 **설계 합의**이며 구현/테스트/배포 완료 선언이 아니다.
- 기존 활동 기록 입력 UX 작업과 P0 데이터 보호를 중단하거나 덮어쓰지 않는다. 실제 코드와 최근 변경을 먼저 확인한다.
- 영수증→식사/활동/소비 연결은 별도 흐름이다. 결제 원장 중복 방지와 인식 결과 사용자 확인이 전제이며 이번 운동 UX 작업에 무단 포함하지 않는다.
- 기록 중단 후 재시작 안내는 실제 과거 기록 기반·선택적으로 제공하며 압박이나 임의 칭찬을 피한다. 별도 제안으로 관리한다.
