> 공통 원칙: [PRODUCT_VISION.md](PRODUCT_VISION.md), 실행 순서: [PROJECT_GUIDE.md](PROJECT_GUIDE.md).

## 관찰된 사용 시나리오와 문제

- 헬스장 도착 후 스트레칭하고, 빈 기구와 컨디션에 따라 그때그때 운동을 정한다. 정해진 순서 강제는 부적절하다.
- `러닝머신 5 5`로 워밍업하고, `어시스트 풀업 55 15 3`으로 목표를 적는다. 실제로 15회를 못 하면 같은 입력창의 긴 운동 텍스트를 다시 수정해 `어시스트 풀업 55 15 2 어시스트 풀업 55 12 1`처럼 고친다.
- 한 입력에 여러 운동을 넣어 기록했을 때 어시스트 풀업·체스트프레스에서 선택한 상체 자극 부위가 런지의 하체 자극 선택 화면에도 체크된 것으로 보였다. **실제 저장 데이터 혼합인지 UI 선택 상태 공유인지는 미확인**. 재현 및 저장·재진입 검사 필요.
- 휴식 타이머가 기술적으로 고장 난 것으로 확인된 것은 아니다. 현재 기록 방식이 세트 완료 시점을 표현하지 못해 **실사용에서 타이머를 활용하기 어렵다**는 문제다.
- 운동 중 휴대폰 조작을 최소화하고 싶지만, 어떤 날은 세트마다, 어떤 날은 운동을 마친 뒤 몰아서 기록한다. 사용자가 두 방식을 미리 선택하도록 강제하지 않는다.

## 결정된 UX 원칙

1. **입력창 하나, 운동 항목은 독립적으로.** `운동명 kg 횟수 세트`, `러닝머신 속도 분` 등 기존 한 줄 문법을 유지한다. 여러 운동을 한 번에 붙여 넣는 기존 기록도 유실 없이 읽을 수 있어야 한다. 새 운동 추가는 기존 긴 텍스트 전체를 다시 편집하지 않아도 된다.
2. **운동 세션 → 운동 항목 → 세트**의 개념을 분리한다. 실제 데이터 스키마 변경 여부는 코드 확인 후 결정한다. 자극 부위는 운동 항목별로 독립 관리하고 예상 부위와 실제 체감 부위를 혼동하지 않는다.
3. **목표와 실제 수행 구분.** 목표 `55 15 3`은 보존하고, 수행 중 3세트째 12회를 했다면 해당 세트만 수정한다. 같은 횟수를 묶어 입력하든 개별 수정하든 최종 세트별 결과는 동일하게 보존한다. 기존 원문도 보존한다.
4. **기록 방식 전환을 강요하지 않는다.** 세트별 완료와 운동 종료 후 일괄 입력을 같은 운동 항목에서 자유롭게 사용한다. 일괄 완료/과거 입력은 타이머를 자동 시작하지 않는다.
5. **휴식은 별도 설정 화면보다 자연스러운 흐름.** 세트 완료를 누르면 경과 시간 표시를 시작하고 다음 세트 시작으로 종료한다. 고정 카운트다운·재촉을 기본으로 강요하지 않는다. 알림/진동은 선택 기능이며 브라우저 백그라운드 동작을 실제 검증하기 전에는 보장하지 않는다. 세트 완료 취소·수정 시 휴식 상태도 일관되게 처리한다.
6. **상황별 화면은 같은 기록을 공유.** 운동 중에는 현재 운동·세트·휴식만 간결하게, 사후 편집에는 일괄 입력·수정을, 회고에는 실제 기록 비교를 보여준다. 별도 화면 신설/큰 재배치는 코드 검토와 범위 합의 후 단계적으로 진행한다.
7. **정확한 비교.** 어시스트 풀업의 55kg은 보조 중량이므로 일반 중량과 같은 방향으로 성장을 해석하지 않는다. 일반 러닝머신은 경사 입력을 요구하지 않는다. 미입력/미완료를 실제 수행으로 확정하지 않는다.

## 우선 구현/검증 시나리오

1. **원인 조사:** 한 기록에 어시스트 풀업·체스트프레스·런지를 입력하고 각각 자극 부위를 달리 선택한다. 다른 운동으로 전환/저장/재진입/기기 동기화 시 체크 UI와 저장값을 별도로 확인한다.
2. **기존 기록 보존:** 단일 운동, 여러 운동이 이어진 원문, 0kg, 보조 중량, 유산소, 운동별 서로 다른 세트 횟수, 사진·활동 시간·기존 동기화 데이터를 회귀 검사한다.
3. **작은 구현:** 운동별 독립 선택 상태 및 기존 파서의 실제 오류부터 고친다. 그다음 한 줄 추가→운동별 카드/세트 편집→세트 완료/일괄 기록→휴식 경과 측정 순서로 검증 가능한 작은 묶음으로 진행한다.
4. **휴식 시나리오:** 세트 완료 시 시작, 다음 세트 시작 시 종료, 일괄 입력 시 미시작, 취소·화면 이탈·복귀·백그라운드 제한 확인. 화면 밖 정확도는 종료 시각 기반으로 설계·검증한다.
5. **사용성 기준:** 운동기구 앞에서 다음 운동을 추가할 때 기존 기록 전체를 수정할 필요가 없는가? 실제 횟수가 달라져도 한 세트만 고치면 되는가? 다른 운동의 자극 부위가 섞이지 않는가? 운동 중 불필요한 타이머 조작을 요구하지 않는가?

## 범위 경계

- 본 문서는 **설계 합의**이며 구현/테스트/배포 완료 선언이 아니다.
- 기존 활동 기록 입력 UX 작업과 P0 데이터 보호를 중단하거나 덮어쓰지 않는다. 실제 코드와 최근 변경을 먼저 확인한다.
- 영수증→식사/활동/소비 연결은 별도 흐름이다. 결제 원장 중복 방지와 인식 결과 사용자 확인이 전제이며 이번 운동 UX 작업에 무단 포함하지 않는다.
- 기록 중단 후 재시작 안내는 실제 과거 기록 기반·선택적으로 제공하며 압박이나 임의 칭찬을 피한다. 별도 제안으로 관리한다.

**원인**
- 한 줄 종목 추가(`#workout-append-line`)는 capture의 접힌 `추가 설정` → 운동 패널에만 있다.
- 저장 후 진행 중 운동은 아젠다 `workoutBody`에서 세트·휴식만 가능하고 종목 추가 UI가 없다. `writeWorkoutText('log')`는 세트 변경용으로만 쓰인다.
- 「활동 끝내기」는 아젠다 진행 중 카드에만 있어, 모바일에서 capture·개요·일정 아래로 스크롤해야 한다.

**권장 → 로컬 구현(2026-11-08, 푸시·배포 미함)**
1. 일반 캡처: 운동 시작. 종목 추가는 오늘 진행 중 `.live-workout-session`(record-column 우선, 모바일 order -1).
2. 세션 카드 상단: 한 줄 입력 + 추가 → `appendWorkoutLine` + `writeWorkoutText('log', id)`. `workoutAppendBusy`로 연속 클릭 중복 방지. 세트·휴식·자극·골라 담기 재사용. 아젠다 동일 기록은 compact 안내.
3. `.ongoing-finish-bar`: 진행 중만, 모바일 하단 nav·safe-area 위, 제목 한 줄 말줄임. `finish-activity`·명시 end 로직 미변경.

## 세션 제목 혼동 조사 (2026-11-08, 구현 전)

**관찰:** `러닝머신 5.5 5`로 시작 후 같은 log에 `어시스트풀업 50 12 3`을 추가해도 세션 제목·종료 바는 계속 첫 줄 `러닝머신 5.5 5`.

**원인:** `activityTitle(l)` = `l.text`의 **첫 줄**. `appendWorkoutLine`은 새 줄을 **뒤에** 붙이므로 첫 줄은 고정. 러닝머신 `5`분은 종목 파서의 유산소 분이며, 활동 구간(`activityIntervals`)이나 제목 전환 타이머가 아님. 세션 벽시계는 log `time`~`endTime`/다음 활동 한 구간.

**통계:** `kind==='운동'`·`workoutSession(text)` 집계. 표시 제목 문자열이 분류/세트/유산소 합산을 바꾸지 않음.

**권장 → 로컬 구현(2026-11-08, 푸시·배포 미함):** `workoutSessionHeading`/`workoutSessionSummary`로 진행 중 `운동 중`, 종료 `운동`, 요약 `N종목 · N세트 · 유산소 N분`(빈 항목 생략). 세션 카드·종료 바·종료 기록 헤더만. 개별 종목·원문·통계·동기화 불변.

## 휴식 타이머 UX (2026-11-08)

**문제:** 세션 상단의 `60·90·120초`와 세트 완료 자유 휴식이 함께 보여 언제 무엇을 누르는지 헷갈림.

**로컬 구현(푸시·배포 미함)**
1. 기본: 세트 완료 → 해당 **근력** 종목 근처 `휴식 중 · MM:SS` + `다음 세트 시작`. 기존 `startElapsed`/`sessionStorage` 재사용.
2. 선택: 위젯 안 `목표 휴식` details의 60/90/120. 종료 시 세트 자동 시작·완료 없음(경과 표시로 전환).
3. 유산소 카드에는 세트 휴식 UI 없음. 세션/캡처 상단 카운트다운 줄 제거.
4. 과거·일괄 입력은 기존처럼 타이머 미시작.
5. **순서 비강제:** 등록 순서와 무관하게 아무 근력 종목의 세트만 완료해도 됨. 휴식 무시·다른 종목 먼저 수행·한 줄 추가만 해도 `text` 기록은 유지. 종목 추가가 세트 완료/수행 완료를 자동 표시하지 않음.

## 실사용 피드백 (2026-11-10 · 헬린이 시나리오)

**관찰**
- `어시스트풀업 55 12 3` 3세트 완료 표시 후에도 휴식 타이머가 계속 돌고, `체스트프레스`를 추가해도 위쪽에 타이머가 남아 헷갈림.
- 완료된 세트「완료됨」이 `세트 완료` 버튼과 같은 형태라 완료/동작이 구분되지 않음.
- 등록 세트가 끝나면 자극 부위·다음 운동 추가가 바로 보이길 원함.
- 공복 등 컨디션에 따라 계획이 바뀌고, 이어서 볼 유튜브 홈트 영상을 찾아 들어가는 게 불편 → 자주 보는 영상 즐겨찾기 희망.
- 헬스장 기간이 약 한 달 남고 이후는 등산·산스장·유튜브 홈트가 유력. 기록 형태가 바뀔 예정(기존 조사와 일치).

**권장 기본안 (이번 구현 범위)**
1. 완료 표시는 버튼이 아닌 `완료` 상태 표시 + 조용한 `되돌리기`. `세트 완료`만 버튼.
2. 그 종목의 **마지막 세트**를 표시하면 세트 사이 휴식을 **끊음**. 다음 운동을 한 줄 추가하면 남은 휴식도 정리.
3. 종목 세트 표시가 끝나면 그 카드 바로 아래에 자극 부위(저장 기록) + 운동 한 줄 추가를 붙임.

**휴식 시간을 따로 저장할까? (헬린이 질문 · 기본안)**
- **지금은 수동으로 휴식 초를 적는 칸을 만들지 않음.** 운동 중 입력 부담만 늘고, 이미 `세트 완료`→`다음 세트 시작` 탭 간격으로 경과를 보고 있음.
- 나중에 효율 비교가 필요하면, 그 탭 시각을 **선택적으로** 기록에 붙이는 쪽이 맞음(사용자가 초를 기입하는 필드 X). 스키마·동기화 변경이므로 **별도 승인 전 구현 금지.**
- 종목 사이 휴식까지 분석하려면 “다음 종목 첫 세트 완료” 시각과 구분해야 해서, 당분간은 UI 정리만으로 충분.

**유튜브 영상 즐겨찾기 (후순위 · 미승인)**
- 기본안: 기존 즐겨찾기에 **링크형**(제목+URL)을 두고, 운동 세션/캡처에서 바로 열어 홈트에 이어가기. 새 메뉴·외부 계정 연동은 하지 않음.
- 착수 전 승인 필요. P3/후순위에 기록.

**헬스장 이후**
- 등산·산스장·홈트는 세트 UI가 과할 수 있음 → 기존「헬스장 외 운동」표시 축소 방향 유지. 파서/스키마 대개편은 자동 승인 아님.

## 한 손 조작 피드백 (2026-11-08)

**관찰:** `다음 세트 시작` 후 다시 세트 행의 `세트 완료`를 찾으려면 손가락을 옮기고, 종목 추가 입력도 세트 위에 있어 스크롤이 늘었다.

**기본안 → 로컬 구현(푸시·배포 미함)**
1. 휴식 위젯 **같은 자리** 기본 버튼: 휴식 중 `다음 세트 시작` → 남은 세트가 있으면 `ready`로 전환되어 같은 버튼이 `세트 완료`가 됨 → 누르면 해당 종목의 첫 미완료 세트를 완료하고 다시 자유 휴식. 남은 세트가 없으면 휴식만 종료. 연속 탭으로 두 세트가 한 번에 완료되지 않게 `ready`를 즉시 이탈.
2. 세트 행의 `세트 완료`/`완료됨` 토글은 **진행 중 활동**과 캡처 초안에서만. 오늘이라도 종료된 기록·과거 날짜는 세트 완료/휴식 없음(kg·회 수정은 가능). 일괄 입력은 자동 휴식 없음.
3. 진행 중 `.live-workout-session`의 **운동 한 줄 추가**는 세트 리스트 **아래**로 이동. 골라 담기도 그 아래. 캡처 운동 패널은 원래 세트 아래 추가라 유지.

## 실사용 등록 패턴 (한산/붐빔) · 계획 vs 실제 조사 (2026-11-08)

**사용 패턴:** 한산하면 여러 줄을 한 번에 등록, 붐비면 러닝머신 등 워밍업 후 기구가 빌 때마다 한 줄씩 추가. 둘 다 같은 세션·같은 입력 경로이며 **모드 분기 없음**(캡처 여러 줄 + 세션/캡처 `appendWorkoutLine`).

**현재 구분 (스키마 변경 없음)**
| 구분 | 저장 위치 | 의미 |
|---|---|---|
| 실제 기록 정본 | `logs[].text` | 한 줄 문법 원문. 통계·동기화·MD의 근거 |
| 목표 스냅샷(선택) | `logs[].workoutPlan` | 최초 저장(또는 지난 운동 불러오기) 때 고정. 이후 text가 바뀌어도 덮지 않음. UI에 `목표 …` 라벨 |
| 세트 완료 표시 | 메모리/`sessionStorage` 초안만 (`liveWorkoutDone`·`workoutSetDone`) | 휴식 UI용. **동기화·백업에 안 넣음** |

**한계 (임의 스키마 변경하지 않음)**
- text에 적힌 종목/세트는 “아직 안 함 / 건너뜀 / 수행함”을 **필드로는 구분하지 못함**. 숫자를 고치면 그게 곧 기록이다.
- `workoutPlan`은 종목별·세트별 수행 여부가 아니라 **첫 스냅샷 문자열**이다. 나중에 추가한 종목에는 plan 라벨이 없을 수 있다.
- “등록만 하고 수행은 안 한 세트”를 데이터로 남기려면 새 필드(세트 상태 등)가 필요 → **미구현·미승인**. 지금은 UI 완료 토글·휴식만 선택적으로 쓰고, 기록은 text 수정으로 충분하다.

**최소 변경 방침:** 일괄/한 줄 병행·순서 무시·추가≠완료를 코드/테스트로 보장. 계획/실제 스키마 분리는 별도 승인 전까지 하지 않음.

## 헬스장 외 운동(등산·홈트·댄스) 조사 (2026-11-08, 스키마 미변경)

**전제:** 활동 분류는 계속 `운동` 하나. 등산/홈트/헬스 **모드 선택 강제 없음**. 한 줄 문법·과거 `text` 유지. 파서가 모르는 값을 거리·고도로 추측하지 않음.

### 파서가 실제로 하는 일 (`parseWorkout`)

| 입력 예 | 결과 | 비고 |
|---|---|---|
| `랫풀다운 20 10 3` | `strength` | kg·회·세트 |
| `러닝머신 5.5 5` / `천계 4 5` | `cardio` | 속도·분만 (화이트리스트 종목) |
| `마이마운틴 10 4 20` | `incline` | 각도·속도·분 |
| `관악산 등산` / `유튜브 홈트 30분` / `설악산\n거리 12km` | **memo(원문 보존)** | 숫자 문법 불일치 → 운동 종목으로 해석하지 않음 |
| `홈트 20 10 3` / `북한산 8 2 1` | **오인 strength 가능** | 이름+세 숫자가 정수 회·세트면 근력으로 읽힘. 등산·홈트 전용 문법 없음 |

`workoutSessionSummary`: 파싱된 종목·세트·유산소 분만. memo-only면 요약 문자열 없음 → 제목은 그래도 `운동 중`/`운동`(표시 작업).

### 분류 (`classifyActivity`)

- 파서가 exercise를 내거나 키워드(헬스 기구·러닝·스트레칭 등)가 있으면 `운동`.
- `등산`/`홈트`/`유튜브`/`댄스`는 **키워드 목록에 없음** → `관악산 등산`, `유튜브 홈트`는 기본 **`일상`**. 사용자가 배지에서 `운동`을 고르면 `manualKind`로 유지.
- Apple Health `Hiking` 연결 힌트(`health-state`)만 텍스트에 `등산|하이킹`을 볼 뿐, 기록 UI/파서와는 별개.

### UI·휴식과의 관계 (제목·휴식 작업과 충돌 없이)

- **세트 완료·휴식 타이머:** `strength` 세트 행에만 붙음. memo-only·유산소-only에서는 세트 완료/휴식이 **안 뜸**(현재·이번 휴식 UX와 동일).
- **진행 중 세션 카드:** `kind==='운동'`이면 파서 결과와 무관하게 한 줄 추가·골라 담기·(종목 있으면) 세트 UI·운동 느낌 버튼이 보일 수 있음. 등산/홈트 memo만 있을 때도 헬스장용 힌트·자극 부위 버튼이 남아 **과잉 노출** 가능.
- **활동 시간:** 등산/홈트도 `time`~`endTime` 구간으로 측정. 거리·고도 필드는 **없음**(text 자유 기술).

### 권장 개선(승인 전 보고만 — 미구현)

1. **지금 해도 되는 표시 정리(스키마 없음):** memo-only/`strength` 0건이면 세트·휴식·골라 담기 강조를 줄이고 원문·활동 시계 위주. 제목은 계속 `운동 중`/`운동`. 근력 문법 줄이 생기면 기존 세트 UI 재노출.
2. **분류 키워드(선택):** `등산`/`하이킹`/`홈트`/`유튜브`/`댄스`를 운동 키워드에 넣어 수동 선택 부담 감소. 파서 해석은 바꾸지 않음.
3. **오인 방지(신중):** 지명·홈트명이 `N N N` 근력으로 읽히는 경우 — 화이트리스트/금지어 없이 넓히면 위험. **승인 전 금지.** 사용자는 문장형 memo로 적는 현황 유지.
4. **새 필드(거리·고도·영상 URL 등):** 스키마/동기화 영향 → **별도 승인 전 금지.** 당분간 text + 활동 시간으로 충분.

**이번 제목·휴식 커밋 범위:** 헬스장 근력 휴식 UX·세션 제목만. 등산/홈트 전용 파서·스키마는 넣지 않음.

## 기록 시점(진행 중 vs 사후) 조사 (2026-11-08)

**사용 패턴:** 헬스장·홈트는 시작→진행 중 기록→종료. 등산은 Watch로 측정 후 **끝난 뒤** Haze Flow에 요약. 종류별 모드 강제 없음. Apple Health 자동 연동은 **향후 후보(이번 범위 밖)**.

### 기존 구조 재사용 가능 여부

| 흐름 | 현재 지원 | 경로 |
|---|---|---|
| 지금 시작·진행 중 기록 | 있음 | 캡처 `▶ 활동 시작` → `time`만 저장, `memo=false` → 진행 중. 종목 추가/세트/종료 바. `finish-activity` 또는 다음 활동 시작으로 종료 |
| 홈트처럼 시작 후 직접 종료 | 있음 | 위와 동일 + `■ 끝내기` |
| 이미 끝난 운동을 시작·종료와 함께 남기기 | **부분** | **수정 화면**에 `time`/`endDate`/`endTime`/`timeEstimated`·활동/짧은 기록 전환이 이미 있음. 캡처 저장 시에는 **시작 시각만** 받고 종료 필드는 없음 |
| 소요 시간만(절대 시각 없이) | **없음** | duration 전용 필드 없음. text에 「4시간」을 적어도 구간 분으로는 안 씀 |
| 짧은 기록(memo) | 있음 | `memo=true` → `activityIntervals`에서 **제외**(시간 구간 없음). 등산 사후 메모로는 가능하나 소요 분·타임라인 구간은 안 남음 |

캡처에서 과거 시작만 넣고 종료를 안 주면, 끝난 등산도 **진행 중**으로 길게 잡혀 종료 바가 뜬다. 사후 완료 구간을 남기려면 지금은 저장 후 수정에서 종료를 넣어야 한다.

### 완료 vs 실제 수행 구분 (추정 금지)

- 활동 구간 종료(`endDate`/`endTime` 또는 다음 활동) ≠ 근력 세트 완료(UI 전용) ≠ text에 적힌 종목이 “수행됨”.
- text에 있는 숫자는 곧 기록 정본이며 “등록만/수행함/건너뜀” 필드는 **없음**. 추정·새 스키마 없음.

### 세트·휴식 UI (세트가 없는 운동)

- `strength` 없을 때 세트 완료·휴식 타이머는 **이미 안 뜸**(유산소·memo).
- 다만 진행 중 `live-workout-session`은 `kind==='운동'`이면 한 줄 추가·골라 담기·자극 버튼 등이 남아 등산/홈트 memo에 **헬스장 톤이 과할 수 있음** → 표시 축소는 스키마 없이 가능(승인 후).

### 설계 결정 필요 (구현 전)

1. **캡처에서 종료 시각(또는 시작+종료) 선택 입력**을 추가할지. 스키마는 기존 `endDate`/`endTime` 재사용. 사후 등산 부담을 가장 줄이는 최소 변경.
2. **소요 분만** 받는 UI를 둘지. 내부적으로 시작+종료로 환산하거나 text만 둘지 — 환산 규칙을 정하기 전 구현하지 않음.
3. memo-only/`strength` 0건일 때 세션 카드의 헬스장용 컨트롤 축소 범위(한 줄 추가·골라 담기·느낌 버튼 중 무엇까지).
4. Health 가져오기→운동 연결은 기존 기능 유지, **자동 동기·중복 입력 제거는 이후 과제**.

**제목·휴식 작업과의 관계:** 진행 중 제목 `운동 중`·자유 휴식은 헬스장 진행 흐름에 맞춤.

## 최소 구현 (2026-11-08, 로컬 · 푸시·배포 미함)

1. **캡처 선택 종료:** 추가 설정의 종료 날짜·시간. `captureActivityEnd` → 기존 `endDate`/`endTime`. 비우면 진행 중, 채우면 즉시 완료. memo 모드에서는 숨김·무시. 소요 분만 입력은 없음.
2. **세트 없는 UI:** 세트 완료·휴식은 strength만. 종목 한 줄 추가는 유지. 골라 담기/지난 운동은 details. 자극(느낌)은 strength 또는 기존 feedback이 있을 때만.
3. **제목·휴식:** `운동 중`/`운동`+요약, 자유 휴식 기본·목표 details, 순서 비강제.
4. Health 자동 연동·duration-only·스키마 추가 없음.
