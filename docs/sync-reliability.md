# 동기화 및 활동 종료 수정 (2026-11-02)

재현한 문제:

- 생활 상태의 `bodyPhotos`가 원격 사진 목록에서 빠져, 다른 기기에서 내려받는 대신 없는 로컬 사진을 올리려고 시도했다.
- 사진 하나의 실패 또는 기록 하나의 충돌이 관계없는 기록 전송까지 중단했다.
- 종료 필드의 빈 문자열과 필드 없음이 다르게 취급되어, 오래된 기기의 빈 종료값과 원격 종료 시간이 거짓 충돌을 일으켰다.
- 수정 화면을 열어둔 동안 원격/다른 탭에서 종료된 기록을 저장하면 오래된 빈 종료 입력이 최신 종료 시간을 지웠다.

수정:

- 컬렉션별 사진 참조를 사용하고, 전송 가능한 기록을 새 사진 업로드보다 먼저 전송한다.
- 충돌한 기록만 보류한다. 사진 전송 오류가 다른 기록의 전송을 막지 않는다.
- 기록과 사진의 동기화 상태를 구분한다. 응답 없는 요청에 제한 시간을 두고 자동 재시도한다.
- 저장할 때 동기화 대기 변경을 즉시 기기에 기록한다. 활동 종료는 바로 전송을 시도하고, 앱 백그라운드/종료 시에도 전송을 시도한다. Safari가 요청을 중단하면 재시작 시 기기 기록에서 이어간다.
- 빈 종료값을 정규화한다. 수정 화면에서 종료 입력을 바꾸지 않았다면 최신 저장소의 종료 시간을 유지한다. 사용자가 직접 종료 입력을 바꾼 경우 그 선택을 유지한다.
- 로그인 확인 중에는 잘못된 로그인 전 저장소에 기록을 쓰지 않도록 저장을 보류하고 안내한다.

검증:

- 인바디 사진 기기 간 다운로드와 활동 종료 왕복 동기화
- 사진 다운로드 실패/업로드 지연/충돌이 있어도 관계없는 종료 전송
- 오래된 빈 종료값, 명시적인 재개, 앱 종료 직후 재시작
- 응답 없는 요청의 제한 시간과 재시도
- 브라우저 두 탭: 수정 화면 열기 → 다른 탭 종료 → 오래된 수정 화면에서 내용 저장 → 양쪽 새로고침 후 종료 유지

실제 아이폰 Safari에서의 재검증은 별도다. 기존 기기의 완료된 종료 기록을 임의의 시간으로 복구하지 않으며, 최신 저장소에 남은 명시적 종료값을 보존한다. 이 수정은 스키마나 계정, 기존 원본 기록을 삭제하지 않는다.

## 2026-11-06 · 증분 조회 식별자 처리

실제 supabase-js의 `in()`은 쉼표가 들어간 문자열을 인용부호로 감싸지만 문자열 안의 인용부호와 역슬래시는 이스케이프하지 않았다. 기록 키는 JSON 배열 문자열이므로 변경된 키를 조회할 때 필터 리터럴을 별도로 이스케이프한다. 저장된 키나 기록 자체는 바꾸지 않는다. 요청 길이 계산도 이스케이프된 문자열 기준으로 한다.

전체 초기 로딩만 시험하거나 두 번째 화면을 새로고침해서 확인하면 이 경로를 놓친다. 실제 SDK로 직렬화된 필터와 첫 로딩 뒤 새 활동·종료 수정의 증분 조회를 검사한다. 클라우드 점검은 두 개의 독립된 기기 저장소와 별도 `sandbox` 공간에서 시행하며 실제 아이폰 카메라 검증과 구분한다.

## 2026-11-06 · 백업 저장 시점과 계정 보호

백업·문서·이미지 내보내기는 진행 중인 IndexedDB 저장 뒤의 최신 기록을 읽는다. 내보낼 기록·날짜·사진 저장소를 고정하고 계정이 바뀌면 다운로드를 중단한다. 백업 가져오기는 저장에 실패했을 때 완료로 표시하지 않으며, 복구 상태는 새 기록이 실제로 저장된 뒤 해제한다. 로그인 확인 중에는 내보내기·가져오기를 보류한다. 자동 검사는 활동 종료 저장 직후 백업과 읽기 중 계정 변경을 확인한다.
