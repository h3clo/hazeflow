## 1. 운영 방식

- 기간: **2026-11-09(월) ~ 11-22(일)**, 14일.
- **날짜에 작업을 강제 배정하지 않는다.** 아래 **작업 큐 순서**로 진행하고, 한 항목의 완료 기준을 충족하면 **즉시 다음 항목**으로 넘어간다.
- 날짜는 **목표 시점·점검일**로만 쓴다. 컨디션·차단 요인에 따라 큐 진행 속도를 조절한다.
- 원칙: 기존 기록·사진·동기화 보존 > 새 기능. 구현 / 자동 검사 / 웹 확인 / 배포 / 실기기 / 계정 반영을 섞어 완료로 쓰지 않는다.
- 로컬 UX WIP와 원격 12커밋을 **덮어쓰거나 삭제하지 않는다.** `git pull`/`reset`으로 미커밋 파일을 지우지 않는다.
- 실제 계정 데이터 변경·배포·커밋/푸시는 **별도 사용자 승인** 전까지 금지.
- 이 문서는 앱 개인 할 일에 넣지 않는다.

### AI 사용량 절약 규칙

1. 작업 시작 전 **재사용 목록**만 읽고, 관련 없는 문서·폴더를 전부 재탐색하지 않는다.
2. **완료 기준**을 충족하면 같은 주제를 재설계·재설명하지 말고 큐의 다음으로 이동한다.
3. **중단 조건**에 해당하면 근거·예상 잔여 시간을 가이드/이 계획에 한 줄로 남기고 멈추거나 다음 가능한 항목으로 건너뛴다.
4. 이미 통과한 `npm test`/`build`를 문서만 바꾼 뒤 다시 돌리지 않는다. 코드 변경 시에만 해당 범위 검사를 돌린다.
5. 막힌 항목을 AI에게 반복 재시도하기보다 사용자 승인·실기기·원자료 접근이 필요한지 먼저 표시한다.

### 시간·불확실성 표기

- **AI** = 코드/문서 생성·수정 · **검사** = `npm test`/`build`/웹 sandbox · **실사용** = 사용자·실기기

## 6. 별도 작업 큐 — iCloud 정리

개발 큐와 **섞지 않는다.** 커밋·배포·결제 반영과 한 세션으로 묶지 않는다.  
**현재 계획 문서 작성 시점에는 iCloud에 접근·변경하지 않았다.** 경로 원문은 공개 문서에 쓰지 않는다.

| ID | 단계 | 내용 | 예상 시간 | 상태 |
|---|---|---|---|---|
| I0 | 현황 조사 | `.private/data-locations.md` 존재·경로 유효성, 폴더 규모·중복 양상 파악 (원문 공개 복제 금지) | 경로 확인 L: 0.5h · **전체 규모·정리량: 미확인** (접근·목록화 전 산정 불가) | 미착수 |
| I1 | 백업 확인 | 정리 전 백업/사본이 있는지, 휴지통·이미 정리한 사본 재삭제 금지 규칙 확인 | **미확인** (백업 위치·용량 미조사) | 미착수 |
| I2 | 정리 | 중복·잘못된 위치 정리. 앱 계정 데이터·Git과 분리 | **미확인** (I0 결과에 비례) | 미착수 |
| I3 | 검증 | 필요한 자료가 새 위치에서 열리는지, `.private` 경로만 갱신 | I0 규모 알면 추정 · 현재 **미확인** | 미착수 |

**중단 조건:** 주문/소득 원문을 공개 가이드에 넣을 뻔하면 중단. 자료 없다고 재수집하지 않음. 개발 Q와 충돌하면 iCloud를 멈추고 개발 큐 우선(또는 그 반대 — 사용자가 그날 지정).
