# 개인 데이터 · Git/배포 경계 (2026-11-12)

## 규칙

- 사용자의 **할 일·루틴·일기·생활 목표·개인 백업**은 Git 커밋·GitHub Pages·`public/` 정적 파일로 올리지 않는다.
- 저장·동기화는 기존 **계정별 IndexedDB + Supabase `hazeflow_records`(RLS)** 만 사용한다.
- 실계정에 기록을 넣을 때는 **로그인한 본인 세션**으로만 한다. 공개 JSON 병합 시드·에이전트 service_role·타인 계정 쓰기를 쓰지 않는다.
- 테스트·문서는 **합성·비개인** 문구만 쓴다. 실제 생활 목표 문구를 복제하지 않는다.
- 앱 내 **할 일 여러 줄 붙여넣기**는 로그인 사용자 기기에만 저장·동기화한다. 입력 원문을 분석 서비스·서버 로그·공개 저장소로 보내지 않는다.

## 2026-11-12 조치

PR #50에서 개인 생활 목표 시드가 `public/imports/`에 올라가 Pages로 노출됐다. 후속 PR에서 해당 공개 파일·생성기·개인 안내 문서·관련 테스트를 **트리에서 삭제**하고, 위 규칙을 AGENTS·gitignore에 고정한다. **기존 사용자 IndexedDB/Supabase 기록은 삭제하지 않는다.**

## Git 기록

삭제 커밋 이후 **현재 트리·Pages에는 파일이 없다.** 다만 과거 커밋·PR #50 diff·Actions 아티팩트 캐시에는 내용이 남을 수 있다. 히스토리 rewrite(`git filter-repo` 등)는 force-push·협업 브랜치 재기반·열린 PR 깨짐을 유발하므로, 필요 시 영향 보고 후 사용자가 승인할 때만 한다.
