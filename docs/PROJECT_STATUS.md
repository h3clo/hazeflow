# Haze Flow — 현재 인계 상태 (2026-11-15)

> 최신 사용자 확인과 GitHub main 코드 대조를 반영한 **현재 상태**. 과거 개발 기록은 `PROJECT_GUIDE.md`, `handoff-history.md`에 유지한다. 이 문서의 작업 후보는 개발·병합·배포 승인이 아니다.

## 현재 실행 경계

- **Haze & Co. 통합 설계·대화·GitHub 감사 진행 중.** 사용자 명시적 재개 승인 전에는 앱 코드·운영 DB·배포·실계정 데이터를 변경하지 않는다.
- `AGENTS.md`의 과거 자율 PR 병합·Pages 배포 규칙과 `PROJECT_GUIDE.md`의 오래된 '완료 즉시 다음' 지시보다 **현재 중단 결정이 우선**한다.
- 다음 작업은 Git main/PR/로컬 미커밋 변경을 확인하고 문서·요구사항·QA 계획 정리부터 진행한다.

## 검증된 사실

| 영역 | 최신 상태 | 근거 수준 |
| --- | --- | --- |
| Watch 활동 표시·동기화 | **사용자가 실제 Watch에서 수정 반영 및 정상 동기화를 확인함** | 사용자 실기기 확인. 과거 문서의 미검증 문구는 당시 기록 |
| Watch 계정 경계 | `watch-snapshot.js`, 관련 테스트, iOS Watch relay/session 코드 존재 | 코드·테스트 존재 확인. 모든 예외 상황 실기기 통과로 확대 해석 금지 |
| 운동 입력 | 한 줄 추가, 근력 세트 수정·추가·삭제 코드 및 테스트 존재 | 코드·테스트 존재 확인 |
| 운동 **종목 자체** 삭제·순서 변경 | **미구현(사용자 직접 확인)** | 다음 UX 작업 후보. 세트 삭제와 혼동 금지 |
| 일반 브라우저 QA | Flow QA에서 Haze 활동 시나리오 자동화 코드 존재 | 최근 CI 실행 성공 여부 별도 확인 |
| 격리 QA 서버 | `?sandbox&device=` 로컬 기록 분리 사용 | 운영 계정·클라우드·네이티브 전송까지 차단되는지 **미검증** |

## 다음 작업 후보 (개발 재개 승인 후)

1. 운동 종목 삭제·순서 변경의 UX/데이터 보존 기준 확정, 작은 단위로 구현·검증.
2. Flow QA의 `?sandbox` 안전 경계를 검토하고 부족하면 실제 계정/운영 DB/네이티브 데이터 접근을 막는 **격리 테스트 모드** 보강. 중앙 `docs/ROADMAP.md` Phase 1 P1 후보.
3. 실기기/브라우저/CI 검증 수준을 분리해 회귀 검사 기록. Watch의 **이미 확인된 동기화 정상 동작**을 미해결 버그로 재등록하지 않는다.
4. 중앙 설계에서 다음 제품 버전·우선순위를 확정한 후 앱 작업 재개 여부를 사용자에게 확인한다.

## 인계 전 체크

- 실제 Git 브랜치/커밋/열린 PR과 `docs/PROJECT_GUIDE.md` 대기열을 다시 대조한다.
- 개인 활동 기록·사진·인증 정보는 테스트/커밋/정적 자산에 넣지 않는다.
- 앱 코드 수정, DB 적용, PR 병합, 배포는 이번 문서 정리로 승인되지 않는다.
- 중앙 원본: https://github.com/h3clo/haze-and-co (읽기 권한이 있는 경우만 참조).
