# 기능 재구성 및 점검 — 2026-10-31

## 이번에 반영한 기본 동작

- 루틴은 반복 설정(적용일·요일·시작 시간·순서가 있는 단계·예상 분)으로 한 번 등록한다.
- 해당 요일의 오늘 화면과 주간 계획에 자동 표시한다. 오늘 화면의 단계 체크·시작·완료·건너뛰기는 날짜별 실행 기록이다.
- 실행한 날에는 설정 사본을 함께 보관한다. 설정 변경·중단 후에도 이미 실행한 날의 제목과 단계·체크 상태가 바뀌지 않는다.
- 반복 중단은 오늘 이후 예약 변경도 취소한다. 미래의 실행 완료는 허용하지 않으며, 과거 실행 시 알 수 없는 시간을 현재 시간으로 채우지 않는다.
- 일정의 계획 시간과 실제 시작·완료를 분리한다. 시작·완료 로그는 중복 생성하지 않는다. 실행 초기화는 연결된 로그도 정리한다.
- 시간 없는 할 일, 계획, 반복 루틴을 구분한다. 완료한 할 일은 실제 활동에 연결한다.
- 실제 기록은 공통 기록으로 저장한다. 식사 원문, 정한 숫자 순서의 운동, 생활 메모를 날짜·분류·전체 기간 검색으로 볼 수 있다.
- 기록 모아보기에 월 달력과 기록이 있는 날짜 목록을 제공한다. 직접 기록한 상태 값이 있을 때만 이전 값과 비교한다.
- 일기와 생활 상태는 자동 저장한다. AI 연결 상태를 확인하고, 생성된 초안은 기존 일기를 즉시 덮어쓰지 않고 확인 후 적용한다.
- 내보내기와 복원은 한곳에 모았다. MD·PNG·JSON을 지원하고, 백업 복원은 검증 후 현재 기록 우선으로 병합한다.
- 삭제·설정 변경·실행 변경은 직전 작업을 되돌릴 수 있다. 다른 저장이 발생하면 되돌리기로 그 기록을 덮어쓰지 않는다.

## 기존 기록 보존

기존 localStorage 키 hazeflow-v1을 유지한다. 예전 단순 루틴·날짜별 체크와 일정 실행 로그를 새 구조로 가져온다. 변환 후 최초 저장 전 원본을 별도 키 hazeflow-v1-before-v2에 보관한다. 복원 전 상태는 hazeflow-v1-before-import에 보관한다. 오래된 운동 입력 폼의 기록도 공통 활동 조회에서 읽으며, 수정할 때 원문의 내용으로 옮긴다.

## 범위

저장 방식은 여전히 브라우저 저장과 파일 백업이다. 기기 간 클라우드 동기화, 닫힌 앱의 예약 알람은 구현하지 않았다. AI 서비스 키가 없어 실제 생성 결과는 검증하지 않았다. PNG 내보내기는 기존 방식이며 이미지 디자인 개선은 사용자 요청대로 뒤로 미뤘다. 운동 기록은 입력 표기를 정리하며 코칭·영양 진단이나 자동 칼로리 추정을 수행하지 않는다.

## 카테고리·미리알림 및 디자인 비교 추가

- 활동 카테고리를 버튼으로 먼저 선택하고 본문만 입력한다. 선택한 카테고리는 다음 입력에도 유지하며 글 내용으로 임의 변경하지 않는다.
- 기록 시간은 현재 시각을 기본으로 표시하고 직접 변경할 수 있다. 수동 변경 후 자동 시각 갱신으로 덮어쓰지 않는다.
- 미리알림은 기한 없음, 날짜, 날짜+시간을 지원한다. 전체/오늘·기한 지남/예정/기한 없음/깃발/완료됨 및 사용자 목록으로 분류한다.
- 미리알림 완료는 기한 날짜가 아닌 실제 완료 날짜에 기록한다. 날짜 없는 항목도 JSON과 전체 MD 내보내기에 포함한다.
- 브라우저의 분리된 점검 공간에서 운동 카테고리 선택 후 접두어 없는 '랫풀다운 15 15 3'을 09:15로 저장되는 것과, 기한 없는 미리알림이 오늘 목록에 들어가지 않고 전체·기한 없음에 표시되는 것을 확인했다.
- 자동 검사 28개 및 앱/디자인 샘플의 다중 페이지 빌드 통과.
- /design-samples.html은 같은 예시를 A(밝은 간결형), B(따뜻한 노트형), C(어두운 정보형)으로 비교하는 독립 샘플이다. 실제 데이터 저장과 분리되어 있다. 각 시안을 렌더해 캡처 확인했다. 실제 앱의 전체 디자인을 이 중 하나로 바꾼 것은 아니다.

## A + C 디자인 적용

사용자가 고른 A의 밝고 간결한 색감과 C의 정보 배치를 실제 앱에 적용했다. 넓은 화면은 일정 / 루틴·미리알림 / 활동 입력·최근 기록의 3열이며, 좁은 화면은 세로로 재배치한다. 상단 주간 날짜 줄로 날짜를 바꿀 수 있다. 밝은 화면을 기본으로 하고 어두운 화면 선택을 별도 설정 키에 보관한다.

일정·루틴·기록 데이터 구조는 변경하지 않았다. 자동 검사 28개와 다중 페이지 빌드는 통과했다. 브라우저에서 두 색상 표시와 새로고침 후 색상 설정 유지, 색상을 바꾸는 동안 식사 입력과 수동 지정 시간(08:45)이 유지되는 것을 확인했다. 실제 기록 화면에서 기존 루틴이 표시되는 것도 읽기로 확인했다. 관련 캡처: ac-light.png / ac-dark.png (점검용 데이터).

## 사진 첨부

- 활동·일기에 최대 8장, 사진만 있는 활동, 확대 보기·다운로드·첨부 해제를 추가했다. 이미지 변환과 IndexedDB 저장 실패를 표시한다.
- JSON에는 사진 데이터가 들어가며 복원 시 JPEG 디코딩·크기·해상도를 검사한다. MD 내보내기는 사진이 있을 때 실제 JPEG와 함께 ZIP으로 내보낸다. PNG에도 사진을 그린다.
- 분리된 브라우저 점검 공간에서 활동/일기 첨부, 새로고침 후 유지, 확대 보기, ZIP·JSON·PNG 다운로드, JSON 병합 복원을 확인했다. ZIP의 JPEG 바이트가 JSON 백업과 같은지도 확인했다. 실제 사용자 기록은 수정하지 않았다.
- 자동 검사 35개 및 빌드 통과. 점검 화면: photo-feature.png.

## 과거 비교·주간 회고·즐겨찾기 및 Pages 배포

- 두 날짜의 사진·일기·활동·생활 수치·같은 운동을 나란히 비교한다. 한 달/일 년 전은 월말과 윤년을 고려한다. 빈 수치는 0으로 처리하지 않는다.
- 주간 회고는 월~일 기준, 오늘까지 계획/실행·운동 일수·식사 건수·기분·생활 만족도 평균을 표시한다. 미래 실행과 기록하지 않은 값을 집계/추정하지 않는다. 직접 작성하는 세 가지 회고 메모를 주별 보관한다.
- 식사·운동 즐겨찾기 추가·수정·삭제·기록에서 저장·입력칸 불러오기를 제공한다. 즐겨찾기 수정은 기존 활동에 영향을 주지 않는다. 작성 중인 내용은 덮어쓰지 않는다.
- JSON 및 전체 MD/ZIP에 즐겨찾기와 주간 회고를 포함한다. 이전 백업도 그대로 불러올 수 있다.
- 자동 검사 43개와 Pages 경로(/hazeflow/) 빌드 통과. 브라우저 점검 공간에서 회고 저장 및 화면 이동/새로고침 후 유지, 즐겨찾기 생성→불러오기→양/시간 변경→기록→주간 집계 반영을 확인했다. 390px 화면에서 메뉴 스크롤과 회고 배치도 확인했다.
- 공개 소스에 개인 백업·브라우저 저장 데이터·환경 변수·과거 스냅샷·점검 화면을 포함하지 않는다. GitHub Actions에서 검사 후 정적 배포하도록 구성했다. localhost에서 웹 주소로 이동할 때 JSON 복원이 필요하다는 안내를 빈 웹 버전 첫 화면에 제공한다.

- Site URL과 명시적 운영/로컬 복귀 주소를 저장했고 이메일 인증이 켜져 있는 것을 확인했다. 기본 메일 서비스는 조직 이메일 및 발송 한도 제한이 있으므로 본인 이메일로 최초 로그인 확인이 필요하다.

### 운영 계정과 실제 왕복 확인

사용자의 이메일 인증 후 운영 사이트에서 로그인 완료와 동기화 완료를 확인했다. Safari에서 새로고침한 뒤에도 계정이 유지됐다. `?sandbox=1&device=qa-a`, `qa-b`는 로컬 상태와 IndexedDB를 별도로 사용하며 동일 계정의 서버 점검 공간만 공유한다. A에서 일정 시작 → B에 동일 실제 시작 시각 수신 → B에서 완료와 점검 기록 삭제 → A에서 완료 시각과 삭제 수신을 확인했다. 실제 main 공간의 사용자 기록은 가져오거나 수정하지 않았다. 점검 탭은 닫고 운영 앱으로 돌아왔다.

사진 업로드 선행·다른 저장소의 실제 파일 수신·사진 전송 실패 시 로컬 보존은 자동 검사로 검증했다. 운영 Safari에서 사진 파일 선택 자동화는 완료하지 못했으므로 실제 운영 사진 업로드/다운로드 왕복까지 브라우저에서 확인한 것으로 간주하지 않는다. 운영 계정 상태 캡처는 account-synced-live.png이며 개인 이메일을 포함하지 않는다.

## 활동 입력 발견성 개선

활동 남기기를 오늘 화면 맨 위의 전체 너비 카드로 옮겼다. 강조 테두리·배경·큰 제목과 입력 예시, 명시적인 내용 라벨, 선명한 입력칸, 활동 기록하기 버튼을 추가했다. 데스크톱에서는 제목과 카테고리를 한 줄에 배치해 아래 일정·루틴·최근 기록도 확인하기 쉽게 했고, 모바일에서는 넓은 저장 버튼을 사용한다.

## 계획과 실제 활동 함께 보기

PLAN에 일정·루틴과 실제 활동을 시간순으로 표시한다. 계획은 예정 시각에 두고 실제 시작·종료를 함께 보여준다. 일정 시작/완료 및 루틴 완료 기록은 해당 계획의 접힌 실행 기록에 묶으며, 부모 계획이 없는 기록은 누락하지 않고 활동으로 표시한다. 시간 없는 계획과 시간 미기록 활동을 별도로 모으고 임의의 시간을 부여하지 않는다. 사진은 작은 썸네일로 표시하며 기존 확대 기능을 유지한다. 오른쪽 활동 기록 원본 목록은 기본 접힘이며 펼친 상태는 화면 갱신 중 유지한다. 저장 구조나 기존 기록은 변경하지 않았다.

시간순 정렬·중복 방지·부모 없는 기록·시간 미기록·사진/원문 보존·입력 불변성 검사 7개를 추가해 총 71개가 통과했다. Pages 경로 빌드도 통과했다. 분리된 예시 기록 공간에서 활동 입력 및 삭제, 시간/운동 수정 후 재정렬, 사진 확대, 일정 시작 및 루틴 완료 시 중복 없는 표시, 원본 목록 펼침 유지, 모바일 390px 가로 넘침 없음을 확인했다. 브라우저 오류는 없었고 실제 사용자 데이터는 변경하지 않았다. 예시 캡처: combined-agenda.png.


## 활동 시작·종료와 진행 중 표시

기존 수동 활동도 시작 시각 순으로 다음 활동 시작에 자동 종료되도록 계산한다. 저장 원문을 일괄 변경하지 않아 시간 수정·삭제·기기 동기화 시 같은 규칙으로 재계산한다. 일정·루틴 실행 로그와 짧은 메모는 이 구간을 끊지 않는다. 종료 날짜/시각을 직접 수정하거나 활동 끝내기로 확정할 수 있으며 빈 구간과 자정 넘김을 지원한다. 마지막 활동은 강조 테두리·진행 중 배지·경과 분·끝내기 버튼으로 표시하고 경과 시간은 15초마다 갱신한다. MD에도 구간을 포함하며 JSON과 계정 동기화는 수동 종료/메모 필드를 보존한다.

자동 구간·기존 기록·메모/실행 로그 제외·수동 종료·수정/삭제 재계산·자정/동시각·백업 검증·MD 검사로 총 77개 통과. 분리된 점검 공간에서 입력→자동 종료, 종료 수정, 메모 추가 후 진행 유지, 끝내기→되돌리기와 모바일 390px 넘침 없음을 확인했다. 실제 사용자 기록은 변경하지 않았다. 예시 캡처: activity-intervals.png.


## 운동 한 번에 여러 종목 기록

활동 입력과 수정의 기록 방식 select를 두 개의 라디오 선택 버튼으로 교체했다. 운동은 여러 줄 원문 하나를 운동 한 번으로 저장하면서 종목별 무게·횟수·세트 또는 각도·속도·분을 표시한다. 인식하지 못한 줄도 메모로 보존한다. 지난 운동 불러오기는 원문만 초안으로 복사하며 기존 초안을 덮어쓰지 않는다. 각 종목은 같은 종목의 가장 가까운 이전 기록을 보여준다. 과거 비교의 여러 종목 파싱과 주간 운동 횟수·종목·근력 세트·유산소 분 집계를 연결했고 MD의 여러 줄 운동 요약도 추가했다. 저장 구조는 기존 원문을 유지해 계정 동기화·백업·사진 기능을 그대로 사용한다.

분리된 점검 공간에서 3종목+자유 메모 저장, 지난 운동 불러오기 후 숫자 수정, 이전 종목 수치 표시, 메모 선택 후 분류 변경 시 선택 유지, 주간 운동 2회/6종목/12세트/40분을 확인했다. 390px 가로 넘침과 브라우저 오류는 없었다. 자동 검사 81개와 Pages 빌드 통과. 실제 사용자 데이터는 변경하지 않았다. 예시 캡처: workout-session.png. 인바디 사진 추출과 가계부는 이번 변경에 포함하지 않았다.


## 인바디 측정 기록과 CSV 가져오기

생활 상태에 체중·골격근량·체지방량·체지방률 입력과 결과지 사진 보관, 측정 이력 및 직전 측정 대비 변화 표시를 추가했다. 기존 몸의 변화 수치를 그대로 사용하고 생활 상태 저장은 기존 항목과 병합해 측정값/사진을 보존한다. 체지방률은 과거 비교와 MD에 포함한다. 결과지 사진은 기존 비공개 사진 동기화 경로와 JSON/MD ZIP에 포함한다. 날짜별 한 측정값을 보관하며 사진 OCR/공식 인바디 계정 연동은 구현하지 않았다.

CSV 양식 다운로드, 파일 선택 또는 붙여넣기, 내용 미리보기, 중복 측정일/잘못된 숫자/미래 날짜 거부를 제공한다. 기본 가져오기는 기존 값이 있는 항목을 유지하고 비어 있는 항목만 채운다. 명시적 덮어쓰기 선택 시에만 가져온 측정값으로 바꾸며, CSV의 빈 칸과 다른 생활 기록·사진은 지우지 않는다. 가져오기는 전체 되돌리기가 가능하다.

측정값/CSV 병합·사진 백업 및 동기화 직렬화·MD·이력 검사로 총 86개 통과. 분리된 점검 공간에서 수동 저장→2일 CSV 미리보기 및 가져오기→기존 값 유지/변화 표시, 예시 사진 첨부, 물 섭취량 저장 및 새로고침 후 측정값/사진 유지, CSV 양식 파일 내용, 390px 가로 넘침 없음을 확인했다. 브라우저 오류는 없었고 실제 사용자 데이터는 변경하지 않았다. 예시 캡처: body-records.png. 운영 사진 서버 왕복은 이번에 별도로 검증하지 않았다. 가계부는 아직 추가하지 않았다.


## 원화 가계부 기본형

가계부 메뉴에 상호명·금액·결제수단의 짧은 지출 입력, 같은 상호의 이전 분류 재사용, 수입/지출/이체 상세 입력과 수정·삭제·되돌리기를 추가했다. 거래는 기존 활동 로그에 메모로 저장해 하루 시간표·MD·JSON·계정 동기화에 포함하고 활동 진행 시간을 끊지 않는다. 월 선택, 지출·수입·차액·이체 분리 합계, 분류별 지출과 월 CSV 내보내기를 제공한다. CSV 수식 문자를 이스케이프한다. 생활 상태의 지출 메모는 합산하지 않는다. 은행/카드 연동·외화·영수증 OCR·기존 옵시디언 데이터 가져오기는 포함하지 않았다.

짧은 입력·잘못된 금액·월/유형별 합계·분류 키·백업/동기화 직렬화·활동 구간 유지·MD·CSV 검사를 추가해 총 90개가 통과했다. 분리된 점검 공간에서 지출 5,800원 입력→분류 수정→같은 상호 4,500원 추가 시 분류 재사용, 이체 100,000원 추가 후 지출 합계 10,300원 유지, 삭제/되돌리기, CSV 실제 파일 내용과 새로고침 후 유지, 390px 가로 넘침 없음을 확인했다. 브라우저 오류는 없었고 실제 사용자 데이터는 변경하지 않았다. 예시 캡처: money-records.png.

주간 회고에 가계부 지출·전주 같은 기간 대비 차이·최다 지출 분류를 연결했다. 이체/미래/생활 상태 메모는 제외하고 직접 남긴 지출만 집계한다. 시간대 UTC에서 총 91개 검사와 Pages 빌드 통과.


## 가계부 CSV 가져오기

가계부에 CSV/TSV 파일 선택 또는 붙여넣기, 날짜·유형·상호·금액·분류·결제수단 미리보기와 가져오기를 추가했다. 첨부 예시의 결제일 열 및 점으로 구분한 날짜를 지원한다. 제외한 열을 미리 보여주고 원화 외 통화와 잘못된 날짜/금액은 거부한다. 기본은 기존 거래 및 파일 안의 동일 거래를 건너뛰며, 같은 거래를 여러 번 추가하는 선택을 제공한다. 기존 거래는 덮어쓰지 않는다. 시간은 임의로 만들지 않고 비워두며, 가져오기 전체를 되돌릴 수 있다. 인바디 CSV와 파서를 공유하고 기존 인바디 검사도 유지했다.

UTC 자동 검사 95개 및 Pages 빌드 통과. 분리된 점검 공간에서 3건 가져오기 후 지출 28,800원/이체 100,000원 분리, 재가져오기 시 3건 중복 건너뛰기, 중복 허용 선택, 새 거래만 1건 추가 미리보기와 390px 가로 넘침 없음을 확인했다. 예시 화면: money-import.png. 실제 사용자 기록이나 옵시디언 파일은 아직 가져오지 않았다.


## 아이폰 사진 호환성 보강과 기록 기반 일기 초안

사용자가 아이폰에서 촬영한 사진이 오류 없이 붙지 않는다고 보고했다. 실제 사용자 원본/실기기에서 동일 증상의 원인까지 확정하지는 못했다. MIME이 비거나 image/jpg인 사진은 파일 헤더/별칭으로 판별하고, HEIC 네이티브 디코딩 실패 시 로컬 heic-to 변환을 지연 로딩한다. 사진 입력을 처리 직전에 비활성화하지 않으며, 변환 진행과 실패를 입력칸에 표시한다. 여러 사진은 장별 저장해 한 장이 실패해도 정상 사진은 보존한다. 캔버스 메모리를 해제하고 읽기/인코딩 지연을 처리한다. 변환용 파일을 외부 서비스로 전송하지 않는다. 일반 사진에는 변환 모듈을 내려받지 않는다. 라이선스/소스 안내는 public/third-party에 포함했다.

예시 화면을 HEIC로 변환한 테스트 파일에서 네이티브 실패→변환 중→JPEG 첨부를 실제 브라우저로 확인했다. 손상 JPEG+정상 PNG를 함께 선택했을 때 실패 설명과 정상 사진 유지, 활동 저장/새로고침 후 HEIC/PNG 사진 2장 재표시를 확인했다. 실제 아이폰 원본과 운영 계정 사진 서버 왕복은 별도로 검증하지 않았다.

일기에 ‘오늘 기록으로 초안’을 추가했다. 활동·실행한 일정/루틴·가계부 합계·생활 수치·짧은 메모만 모아 편집 가능한 초안을 만들며 외부 AI를 호출하지 않는다. 기존 일기는 기본 덧붙이기로 보존하고 명시적 교체, 중복 추가 방지, 되돌리기를 지원한다. 브라우저에서 기존 일기 유지/초안 적용/되돌리기, 390px 가로 넘침 없음을 확인했다. UTC 자동 검사 총 100개 및 Pages 빌드 통과. 예시 캡처: journal-draft.png.


## 식사와 지출 한 번에 기록

식사 입력에 선택 금액과 펼쳐 쓰는 가게·결제수단·가계부 분류를 추가했다. 식사 로그 하나에 지출 정보를 연결해 식사 수/활동 구간과 월별 지출/주간 회고를 함께 반영하며 별도 거래를 복사하지 않는다. 기존 식사도 수정에서 금액을 붙일 수 있다. 가계부의 연결 거래 수정은 식사 편집으로 연결하고, 지출 연결 해제는 식사·사진·시간을 보존한다. 일반 활동 삭제는 연결된 지출도 함께 제거하며 기존 되돌리기를 사용할 수 있다. 식사 분류를 바꿀 때는 금액을 비워 연결을 명시적으로 해제하도록 검증한다. 금액은 선택 사항이며 식사만 남기는 기존 동작을 유지한다.

백업/동기화 직렬화·MD·일기 초안·월/주 집계·활동 시간·지출 수정/해제·CSV 재가져오기 중복 방지 검사로 총 105개가 통과했다. 분리된 점검 공간에서 9,000원 식사 저장 후 단일 기록/가계부 반영, 분류 전환 시 입력 초안 유지, 가계부에서 10,000원으로 수정 및 사진 첨부, 지출 연결 해제 시 식사/사진 유지, 되돌리기와 새로고침 후 복원, 390px 가로 넘침 없음을 확인했다. 브라우저 오류는 없었으며 실제 사용자 기록은 변경하지 않았다. 예시 캡처: meal-money.png.


## 사진에서 자동 입력 — 로컬 작업, 미배포

사용자의 배포 방침에 따라 이후 기능은 묶어서 검증한 뒤 배포한다. 이번 영수증/인바디 사진 읽기 변경은 로컬에만 두고 git push/배포하지 않았다.

가계부 거래 작성·수정에 영수증 사진 첨부·확대·보관을 연결했다. 인바디 결과지와 영수증을 선택하면 로컬 Tesseract OCR로 읽어 확인 창을 보여준다. 언어/worker/WASM 파일은 npm 고정 의존성에서 준비해 앱과 같은 출처에서만 불러온다. 사진을 외부 OCR/AI 서비스로 보내지 않는다. 읽기 취소와 기존 값 보호, 항목별 선택 적용을 제공한다. 영수증은 입력칸만 채우고 거래 저장은 별도로 수행한다. 인바디는 확인한 측정값을 저장하며 측정일 변경 시 새로 첨부한 사진만 그 날짜로 옮긴다. 읽지 못한 값은 비워두고 사용자가 보완할 수 있다. 외화/환불 표시나 합계 충돌은 원화 금액으로 추측하지 않는다.

실제 예시 이미지 OCR에서 영수증 상호/날짜/5,800원/카드를 추출→확인→거래 저장 및 새로고침 후 영수증 사진 유지 확인. 인바디 예시에서 3개 측정값과 날짜를 추출했고, OCR이 체중 라벨을 읽지 못해 체중은 빈칸으로 남았다. 체중을 직접 보완한 후 측정일과 4개 값/사진 저장을 확인했다. 단위가 숫자로 오인된 경우를 보완했고, 기존 식사 금액 10,000원을 5,800원 제안이 기본 덮어쓰지 않는 것 및 명시적 선택 적용도 확인했다. 모바일 390px 확인 창 가로 넘침과 브라우저 오류가 없었다. 예시 캡처: receipt-photo-review.png, inbody-photo-review.png.

UTC 자동 검사 111개 및 Pages 경로 빌드 통과. 실제 사용자 영수증/인바디 원본과 아이폰 실기기 OCR은 아직 검증하지 않았다. 촬영 품질과 문서 배치에 따라 인식 누락/오독이 있으므로 확인 후 저장이 필수다. 사진 원문 인식 결과는 임시 화면에서만 사용하며 저장 기록에는 사용자가 확인한 값과 첨부 사진만 남긴다.

배포 없이 localhost 정적 preview에서 /hazeflow/ 경로의 worker/WASM/언어 파일을 실제로 읽어 영수증 상호·날짜·5,800원·카드 추출을 재확인했다. 문자 인식 확인 창 취소 시 거래 입력값이 자동 변경되지 않는 것과 모바일 가로 넘침 없음을 확인했다. 운영 배포는 하지 않았다.


## 아이폰 촬영 복귀 시 무반응 대응 — 로컬 수정, 미배포

사용자가 아이폰 Safari에서 촬영 뒤 오류/미리보기 없이 아무 반응이 없다고 재보고했다. 현재 구조에서는 카메라 복귀 시 계정 동기화에 따른 화면 재렌더가 화면 내부 file input을 교체할 수 있었다. 이 가능성을 제거하기 위해 사진 입력을 body의 별도 고정 영역에 선택 시마다 생성하고 직접 input/change/cancel 이벤트를 연결했다. 촬영(capture=environment, 단일 image/*)과 보관함(일반 선택)을 분리했다. 사진 선택/처리 중 화면 교체를 지연하고 요청 당시 날짜·계정·편집 문맥을 보존한다. 아직 실제 아이폰 원본/실기기로 같은 원인을 재현한 것은 아니다.

선택 요청·파일 전달·처리 상태와 오류를 입력칸에 유지하며, 복귀 후 4초 또는 장시간 파일 미전달 시 보관함 재선택 안내를 남긴다. cancel/빈 파일도 안내한다. 안내 이후 늦게 오는 파일은 버리지 않고 원래 문맥으로 처리하고, input/change 중복 이벤트는 한 번만 처리한다. 이미지 처리와 저장소 응답에도 시간 제한을 둔다. 정상 저장 후 활동 입력의 이전 상태 문구는 초기화한다.

단위 검사 5개 추가로 총 116개 통과. 분리된 브라우저 점검 공간에서 촬영 요청 input이 #content 밖에 유지되는 것, 선택 중 분류 변경/렌더 요청 후 정상 첨부, 파일 미전달 안내가 렌더 뒤에도 유지되는 것, 이후 늦게 전달된 HEIC 변환/첨부와 기존 사진 보존, 고정 입력을 통한 영수증 OCR(5,800원/상호/날짜/카드) 회귀 확인, 콘솔 오류 없음을 확인했다. 캡처: photo-return-feedback.png. 실제 아이폰 Safari 검증 및 운영 배포는 아직 하지 않았다.


## 중복 UI 정리와 하루 마감 — 로컬 작업, 미배포

일기/생활 상태의 자동 저장과 겹치는 저장 버튼을 제거하고, 연결되지 않은 AI 초안 버튼은 표시하지 않는다. 기록 기반 초안과 연결된 AI 초안은 별도 이름으로 구분한다. 반복 입력 안내/즐겨찾기 관리/활동 원문은 접어두고 사진 크기 등 내부 구현 문구를 줄였다. 생활 상태의 식사·지출·감정 중복 입력은 주 입력처(활동/가계부/일기)로 정리하되 예전 값이 있는 경우 ‘이전에 남긴 생활 메모’로 접어 편집/보관한다. 기존 데이터는 삭제하지 않는다.

새 메뉴를 늘리지 않고 일기 화면에 하루 마감을 통합했다. 식사·운동·지출·사진·계획 완료·몸/회복 측정값 및 진행 중 활동을 모아 보고, 진행 중 활동을 끝내거나 마감 표시를 남길 수 있다. 내일 기억할 일을 적고 다음 날짜의 시간 없는 미리알림으로 한 번만 추가할 수 있다. 마감/내일 메모는 기존 일기 저장·동기화·백업·MD에 포함한다.

단위 검사 총 120개, 기존 생활 메모의 백업/동기화 왕복과 일기 없는 날 MD 내보내기 포함. 분리된 점검 공간에서 식사 1건/지출 10,000원/사진 1장 집계, 마감과 내일 메모 새로고침 후 유지, 반복 클릭 시 미리알림 1개 유지, 진행 중 활동 종료, 활동 원문 기본 접힘, 미연결 AI 숨김, 모바일 390px 넘침 없음을 확인했다. 예전 식사/지출 메모를 담은 예시 JSON을 가져와 접힌 영역에서 값이 보존되는 것도 확인했다. 캡처: day-close-cleanup.png. 운영 배포는 하지 않았다.


## 맥북 메뉴 배치·미리알림 보드·자산관리 — 로컬 작업, 미배포

데스크톱 사이드바를 높이가 정해진 세로 flex 구성으로 바꾸고 메뉴만 스크롤하며 안내 문구는 별도 영역을 차지하게 해 겹침을 제거했다. 상단 제목/버튼도 줄바꿈과 최소 너비를 제어한다. 모바일은 가로 스크롤 하단 메뉴를 유지한다.

미리알림은 큰 제목·체크박스·작은 기한/메모·하단 수정 액션을 가진 포스트잇 보드로 변경했다. 필터를 작은 버튼으로 정리하고 중복 영역 제목과 안내를 줄였다. 완료/깃발/수정/삭제 동작은 기존 데이터를 사용한다.

자산관리 탭에 현금/입출금·예금/적금·투자·부채의 원화 수동 잔액, 총자산/부채/순자산, 날짜별 순자산 변화와 잔액 기록을 추가했다. 계좌별 날짜별 최신 잔액을 사용하고 같은 날짜 갱신은 한 기록만 유지한다. 자산 스냅샷은 기존 로그 저장/동기화 경로를 쓰되 활동 타임라인·지출 합계에서 제외하고 MD/JSON에는 보존한다. 은행/시세 자동 조회나 지출에 따른 잔액 자동 차감은 하지 않는다.

UTC 자동 검사 총 124개와 Pages 빌드 통과. 예시 공간에서 1280×650 메뉴 하단 551px/안내 상단 567px로 겹침 없음, 포스트잇 6개와 완료 처리, 자산 추가/같은 날짜 잔액 갱신, 최신 잔액 삭제 후 과거 값 표시 및 되돌리기, 새로고침 후 순자산 2,200,000원 유지, 모바일 390px에서 자산/할 일 가로 넘침 없음을 확인했다. 실제 사용자 데이터는 변경하지 않았다. 캡처: reminders-sticky.png, assets-overview.png. 운영 배포는 보류했다.


## 포스트잇 범위 정정과 모니터용 화이트보드 모드 — 미배포

사용자의 의도는 상시 켜 둔 모니터에서 해야 할 일을 보는 별도 보드였다. 오늘 대시보드와 미리알림 기본 목록의 포스트잇을 제거하고 일반 목록으로 복원했다. 공유 taskRow를 직접 map 콜백으로 전달할 때 index가 스타일 인자로 전달되지 않도록 명시적 호출/boolean 검사를 사용한다. 포스트잇은 미리알림 탭의 화이트보드 모드에서만 생성한다.

화이트보드는 일반 메뉴·날짜 도구를 숨기고 큰 제목과 포스트잇에 집중한다. 오늘/기한 지남/기한 없는 미완료와 전체 미완료를 선택할 수 있고, 완료·되돌리기·편집·새 할 일 추가를 지원한다. 새 저장소 없이 기존 미리알림을 공유한다. #whiteboard 또는 #whiteboard-all 주소를 북마크하면 선택한 모드로 바로 열리며 새로고침 후 유지된다. 자정이 지나면 날짜와 표시 대상을 갱신한다. 목록 복귀 버튼과 Esc를 제공한다.

## 묶음 배포 및 후속 사용성 개선

사용자 요청에 따라 b2b3f24로 보류했던 사진 입력/OCR·하루 마감·자산관리·기본 목록 복원/화이트보드를 먼저 배포했다. 운영의 분리된 점검 공간에서 촬영용 입력으로 HEIC 변환/첨부, 영수증 OCR 상호/날짜/5,800원/카드 인식을 확인했다. 실제 아이폰 실기기 촬영 결과는 아직 별도 확인이 필요하다.

후속 점검에서 보관된 사진을 다시 읽으려면 재업로드해야 하는 불편과, 내일 메모 수정 후 기존 미리알림을 찾거나 갱신하기 어려운 불편을 수정했다. 영수증/인바디/식사 지출 편집 사진에 ‘다시 읽기’를 추가했고 같은 저장 사진으로 OCR을 실행해 사진 개수를 늘리지 않는다. 일기에는 연결된 미리알림 열기와 제목 갱신을 제공하며 사용자가 변경한 기한/목록/깃발 및 완료 상태를 보존한다.

UTC 검사 128개 통과. 예시 공간에서 저장 영수증 재인식 시 5,800원을 읽고 사진 수 1장 유지, 내일 메모에서 제목을 바꿔도 변경한 기한 2026-11-03과 목록 ‘개인’ 유지 확인. 실제 사용자 기록은 변경하지 않았다. 이 두 사용성 개선을 한 묶음으로 후속 배포한다.
